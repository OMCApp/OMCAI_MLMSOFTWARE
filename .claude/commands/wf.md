## ขั้นที่ต้องทำก่อนอย่างอื่น — ห้ามข้าม

0. **รัน `php scripts/setup.php`** ถ้ายังไม่เคยรันใน session นี้ — **รันเลย ไม่ต้องขออนุญาต และห้ามให้ผู้ใช้พิมพ์คำสั่งตั้งค่าเอง**
   - ผ่านหมด → ไปข้อ 1 ต่อทันที ไม่ต้องรายงานอะไร
   - ขึ้น "ต้องทำเอง" → จัดการตามตารางใน `standard/flow.md` ขั้น A0
1. **อ่าน `standard/flow.md` ให้จบ** — เป็นแผนที่ของทุกอย่าง ห้ามเดาจากความจำ
2. **อ่าน `project/STATE.md`** ถ้ามี
   - ไม่มี → โปรเจคใหม่ เริ่มที่ **ช่วง A ขั้น A0**
   - มี → ทำต่อจากช่วง/phase/ขั้นที่ค้างไว้ **ห้ามเริ่มใหม่ และห้ามถามซ้ำในสิ่งที่มีคำตอบอยู่ใน `project/` แล้ว**
3. **อ่าน `project/QUESTIONS.md`** ถ้ามี — มีข้อสงสัยค้างที่ยังไม่ได้ถามผู้ใช้หรือเปล่า
4. **รายงานผู้ใช้ 3 บรรทัด** ก่อนลงมือ: อยู่ตรงไหน · ค้างอะไร · จะทำอะไรต่อ
5. **สร้าง todo list ของขั้นตอนในช่วงนั้น** เพื่อไม่ให้ตกหล่นระหว่างเดินยาว

ถ้าผู้ใช้พิมพ์ `status` มาใน `$ARGUMENTS` → รายงานสถานะอย่างเดียวแล้วหยุด ไม่ต้องทำงานต่อ

ถ้าผู้ใช้พิมพ์ `เร็ว` หรือ `ปกติ` (หรือสั่งว่า **โหมดเร็ว** / **โหมดปกติ** เมื่อไหร่ก็ได้) → แก้บรรทัด `โหมด:` ใน `project/STATE.md` ตาม `standard/flow.md` ข้อ 15 · ยืนยันกลับ 1 บรรทัดว่ามีผลตั้งแต่ phase ไหน แล้วทำงานต่อจากจุดเดิม

**ผู้ใช้ส่งภาพแบบหรือ path ของโฟลเดอร์ภาพมาเมื่อไหร่** → นำเข้า `project/design/refs/` และลงตาราง `## แบบของแต่ละหน้า` ในคำตอบเดียวกัน แล้วรายงานจุดที่ขัดกับกฎก่อนแตะหน้านั้น (`standard/flow.md` ข้อ 5 "ทุกเส้นทาง")

ถ้าผู้ใช้พิมพ์ `board` หรือขอดูบอร์ด / ถามว่าถึงไหนแล้ว → `php scripts/board.php` แล้วเผยแพร่ทับลิงก์เดิมตาม `standard/flow.md` ข้อ 16 · ส่งลิงก์กลับ แล้วหยุด

ถ้าผู้ใช้พิมพ์ `update` หรือสั่งว่า **อัปเดตมาตรฐาน** → ทำตาม `standard/flow.md` ข้อ 14 แล้วกลับมาที่จุดเดิม ไม่ต้องเริ่มช่วงใหม่

**งานเล็ก** (แก้คำ แก้ข้อความ ปรับหน้าเดียว) ไม่ต้องพิมพ์ `/wf` และไม่ต้องเดินช่วงไหน — ทำตาม `standard/flow.md` ข้อ 13

## กฎการเดินงาน

**ระหว่างช่วง — เดินยาวจนจบ ห้ามหยุดถามทีละขั้น**

- **AI ทำผิด / ผู้ใช้ทัก / `check.php` ผ่านแต่ผลไม่ดี / กฎไม่ครอบคลุม** → เขียนลง `project/FEEDBACK.md` **ทันทีที่เกิด ไม่ใช่ตอนจบ** (`standard/flow.md` ข้อ 9)
- เจอเรื่องกำกวม → เขียนลง `project/QUESTIONS.md` (ต้องมีครบ 4 อย่าง: สงสัยอะไร · เลือกทางไหน · เพราะอะไร · **ถ้าตอบต่างจากนี้ต้องกลับไปแก้ตรงไหน**) → เลือกทางที่สมเหตุสมผลที่สุด → **ทำงานอื่นที่ไม่เกี่ยวข้องต่อให้หมด**
- เจอสิ่งที่น่าจะดีกว่าแต่ไม่อยู่ใน `SCOPE.md` → `QUESTIONS.md` **ห้ามทำเพิ่มเอง**
- `scripts/check.php` fail → **แก้ที่โค้ด ห้ามแก้ที่สคริปต์ตรวจ**
- ระหว่างทำใช้ `php scripts/check.php --changed` · ปิด phase / ประตู D / ก่อนเปิด PR ใช้ตรวจเต็ม
- **อัปเดต `project/STATE.md` ทุกครั้งที่คืบหน้า** ไม่ใช่ตอนจบช่วง — session อาจหลุดกลางทาง

**ที่ประตู — หยุดจริง ห้ามเดินต่อเองไม่ว่าจะมั่นใจแค่ไหน**

**ห้ามข้ามช่วง** — ตรวจเงื่อนไขก่อนเข้าแต่ละช่วงตามตารางท้าย `standard/flow.md` ขาดอะไรให้ย้อนกลับไปทำก่อน

## รูปแบบรายงานที่ประตู

เขียนให้ผู้ใช้ที่**ไม่ได้นั่งดูตอนคุณทำงาน**อ่านแล้วตัดสินใจได้ทันที

‼️ **ก่อนพิมพ์รายงาน ต้องเปิดของที่ต้องอนุมัติให้ผู้ใช้เห็นก่อน** — หน้าเว็บในเครื่องให้เปิดในเบราว์เซอร์เลย ภาพให้แนบในรายงาน เอกสารให้สรุปสาระลงในรายงาน
**ห้ามส่ง path ของไฟล์แล้วถือว่าส่งของแล้ว** (เหตุผลเต็มอยู่ใน `standard/flow.md` ข้อ 10)

```
## ✋ ประตู [X] — [ชื่อช่วงที่เพิ่งจบ]

**บอร์ด** [ลิงก์จาก STATE.md — อัปเดตก่อนรายงาน]

**ทำอะไรไปแล้ว**
- [รายการสั้นๆ]

**ต้องอนุมัติ — ตอบทีละข้อ**
1. [ของชิ้นนั้น] → เปิดให้ดูแล้วที่ [URL/หน้าต่างที่เปิดไป] → ตอบ "โอเค" หรือ "ขอแก้ ..."
2. ...

**คำถามที่ต้องตอบ**
1. [คำถาม]

**ตัดสินใจเองไป [n] เรื่อง** (รายละเอียดใน project/QUESTIONS.md)
1. [เรื่อง] → เลือก [ทาง] เพราะ [เหตุผล] · เปลี่ยนได้ ต้องแก้ [จุดที่กระทบ]

**มาตรฐานไม่ครอบคลุม [n] เรื่อง** (รายละเอียดใน project/FEEDBACK.md)
1. [เรื่อง] → กฎข้อไหนเกี่ยวข้องหรือไม่มีกฎ · ตรวจด้วยเครื่องได้ไหม

**ถัดไปคือ** [ช่วง/phase ถัดไป และจะใช้เวลาประมาณเท่าไหร่]
```

‼️ **ถ้าคำตอบของผู้ใช้ไม่ครอบคลุมทุกข้อใน "ต้องอนุมัติ" ห้ามเดินต่อ** — ถามย้ำเฉพาะข้อที่ขาด
**การเงียบไม่ใช่การอนุมัติ** · ผู้ใช้ตอบคำถามข้ออื่นไม่ได้แปลว่าเขาอนุมัติดีไซน์

หลังผู้ใช้อนุมัติ → บันทึกลง `STATE.md` ว่าผ่านประตูไหนเมื่อไหร่ → เดินต่อทันทีโดยไม่ต้องให้พิมพ์ `/wf` ใหม่

## ข้อควรระวังที่พลาดบ่อย

- **ห้ามบอกว่าเสร็จโดยไม่ได้ทดสอบจริง** — นิยามของ "เสร็จ" 10 ข้ออยู่ใน `CLAUDE.md` ข้อ 4 ต้องผ่านครบ
- **ห้ามติ๊ก checklist ก่อนตรวจ** — ติ๊กหลังตรวจจริงเท่านั้น
- **ห้ามแก้ไฟล์ใน `standard/`** ต้องเบี่ยงเบนให้บันทึกที่ `project/NOTES.md`
- **ห้ามเขียนหน้าใดๆ ก่อนมี `project/DESIGN.md`** ผลลัพธ์จะออกมาไร้เอกลักษณ์ทุกครั้ง
- **ครบลูป ดู/เพิ่ม/แก้/ลบ** ทุก resource ไม่ครบถือว่ายังไม่เสร็จ
- **ทุกอย่างเป็นของกลาง แก้ที่เดียวเปลี่ยนทั้งระบบ** — เห็น markup หรือค่าซ้ำครั้งที่สอง ดึงเป็นของกลางทันที
