# Security Standard

> **อ่านทุกครั้งที่แตะ login, สิทธิ์, การรับ input, การอัปโหลดไฟล์, รหัสผ่าน หรือ query**
> โครงสร้างและ convention อยู่ที่ [`rule.md`](rule.md)
> **ต้องเรียก `/security-review` ก่อนเปิด PR ทุกครั้งที่แตะหัวข้อในไฟล์นี้**

> ‼️ ระบบนี้เขียน auth, session, upload และ validation เองทั้งหมดโดยไม่ใช้ framework ที่ผ่านการทดสอบมาแล้ว
> **นี่คือความเสี่ยงที่สูงที่สุดของสถาปัตยกรรมนี้** ไฟล์นี้จึงเป็นไฟล์ที่ห้ามลัดที่สุดในชุดมาตรฐาน

---

## 1. Auth Contract — ใครคือผู้ใช้ที่ล็อกอินอยู่

**ทั้งโปรเจคต้องมีคำตอบเดียวกันว่า "ผู้ใช้ปัจจุบันคือใคร อ่านจากไหน"** — Middleware, audit log และระบบแจ้งปัญหาต้องใช้ค่าเดียวกัน ถ้าไม่กำหนดตายตัวแต่ละคนจะเก็บ session คนละชื่อแล้วเชื่อมกันไม่ได้

- เก็บใน **`$_SESSION['user_id']` และ `$_SESSION['role']` เท่านั้น**
- **ห้ามเก็บข้อมูลผู้ใช้ทั้งก้อนไว้ใน session** — ข้อมูลจะเก่าค้างถ้าผู้ใช้ถูกแก้ระหว่างที่ session ยังไม่หมดอายุ เช่นถูกลดสิทธิ์แล้วแต่ session เก่ายังไม่รู้
- ‼️ **`core/Session.php` เป็นไฟล์เดียวในระบบที่แตะ `$_SESSION` ได้** — Auth, ภาษา, ธีม, flash message และ old input ทุกตัวเรียกผ่านมัน
  > ยกเว้นให้หลายไฟล์เมื่อไหร่ วันที่เปลี่ยนวิธีเก็บ session (เช่นย้ายไปเก็บใน DB เพราะมีหลายเครื่อง) จะต้องไล่แก้หลายที่และจะลืมบางจุดแน่นอน
  > `scripts/check.php` บังคับข้อนี้ให้แล้ว — ไฟล์อื่นที่แตะ `$_SESSION` จะ fail ทันที
- **ต้องมี helper กลางจุดเดียวสำหรับผู้ใช้ปัจจุบัน** — `Auth::id()` / `Auth::role()` / `Auth::check()` ซึ่งอ่านค่าผ่าน `Session` อีกที
- **base Model ต้องใช้ helper นี้บันทึก `user_id` ลง audit log อัตโนมัติ** ห้ามรับ `user_id` เป็นพารามิเตอร์จาก Controller เพราะจะเผลอส่งผิดคนได้

## 2. Authorization — เช็คสิทธิ์ที่จุดเดียว

**เช็คว่าล็อกอินหรือยังและ role ตรงหรือไม่ ต้องทำผ่าน Middleware กลางเท่านั้น** ห้ามเขียนเช็คซ้ำกระจายในแต่ละ Controller เพราะจะมีจุดที่ลืมเช็คหลุดเสมอ

- ผูก Middleware กับกลุ่ม route เช่นทุก route ใต้ `/admin/*` ต้องผ่าน `AdminMiddleware`
- ไม่ผ่านให้ไปหน้า login หรือหน้า 403 ที่ใช้ layout กลาง
- ‼️ **การซ่อนเมนูไม่ใช่การเช็คสิทธิ์** ต้องกันที่ Middleware เสมอ และ**ทดสอบด้วยการเรียก URL ตรง** ไม่ใช่แค่ดูว่าเมนูหายไป
- **สิทธิ์ระดับแถวสำคัญพอๆ กับสิทธิ์ระดับหน้า** — ผู้ใช้ที่เข้าหน้า `/orders/{id}` ได้ ไม่ได้แปลว่าดูใบสั่งซื้อของคนอื่นได้ · **การรู้ id ไม่เท่ากับมีสิทธิ์ดู**
- แถวที่ถูก soft delete (`deleted_at` ไม่ null) ต้องเข้าถึงไม่ได้เหมือนถูกลบจริง ยกเว้น role ที่มีสิทธิ์กู้คืน

## 3. รหัสผ่าน

- ใช้ `password_hash($pw, PASSWORD_DEFAULT)` และ `password_verify()` **เท่านั้น**
- **ห้ามใช้ md5/sha1 ห้าม hash เอง ห้ามเก็บ plain text** เด็ดขาด
- ห้ามส่งรหัสผ่านกลับมาในรูปแบบใดๆ (response, log, audit log, อีเมล)
- ข้อความตอน login ผิดต้องเหมือนกันไม่ว่าจะผิดที่ชื่อผู้ใช้หรือรหัสผ่าน — บอกแยกเท่ากับบอกคนนอกว่าบัญชีไหนมีอยู่จริง

## 4. SQL Injection

**prepared statement บังคับ 100%** ห้ามต่อ string เข้า SQL ไม่ว่ากรณีใด และต้องตั้ง `PDO::ATTR_EMULATE_PREPARES => false`

‼️ ค่าที่ผูกด้วย placeholder ไม่ได้ (**ชื่อคอลัมน์สำหรับเรียงลำดับ ทิศทาง ASC/DESC ชื่อตาราง**) **ต้องตรวจกับ allowlist ที่กำหนดไว้ในโค้ดก่อนใช้**

```php
$allowedSort = ['created_at', 'name', 'status'];
$sort = in_array($_GET['sort'] ?? '', $allowedSort, true) ? $_GET['sort'] : 'created_at';
$dir  = ($_GET['dir'] ?? '') === 'asc' ? 'ASC' : 'DESC';
```

> จุดนี้คือช่องโหว่ที่หลุดบ่อยที่สุดในหน้าที่มีการเรียงลำดับ — และมาตรฐานนี้**บังคับให้ทุกตารางเรียงลำดับได้** จึงเจอทุกหน้ารายงาน

### 4ก. ‼️ ค่าที่มาจาก dropdown ต้อง validate ซ้ำฝั่ง server เสมอ

รายการที่หน้าเว็บเคยเห็น **ไม่ใช่** ขอบเขตของค่าที่ส่งกลับมาได้ · เปลี่ยนค่าใน DOM หรือยิง POST เองใช้เวลาไม่กี่วินาที

```php
// ก่อนบันทึกทุกครั้ง — ค่าที่เลือกได้จริงคือค่าที่ผ่านเงื่อนไขและสิทธิ์ของแหล่งนั้น
if (!$options->allows('users', (string) $request->input('assignee_id'))) {
    $request->addError('assignee_id', __('validation.in', [':field' => __('user.assignee')]));
}
```

- **ยิ่งจำเป็นกับ dropdown ที่ค้นจากฝั่ง server** ([`../standard/components.md`](components.md) ข้อ 3ก) เพราะ `<option>` ถูกเติมด้วย JS ตอนใช้งาน ไม่ได้มีอยู่ตอน render
- เงื่อนไขตายตัวใน `config/options.php` (เช่นเอาเฉพาะที่ยังใช้งานอยู่) **มีผลตอน validate ด้วย** — ค่าที่ถูกกรองออกจากรายการต้องบันทึกไม่ได้เช่นกัน
- **สิทธิ์ของแหล่งข้อมูลอยู่ที่ middleware ไม่ใช่ที่ Controller** — การค้นคือการอ่านข้อมูล คนที่ไม่ควรเห็นรายชื่อ ก็ไม่ควรค้นรายชื่อได้

## 5. XSS

- **ทุก output ที่มาจากผู้ใช้ต้องผ่าน `e()` (`htmlspecialchars($v, ENT_QUOTES, 'UTF-8')`) ก่อนแสดงเสมอ**
- ‼️ **รวมถึงหน้าแอดมินด้วย** — ข้อความที่ผู้ใช้ส่งเข้ามาแล้วแอดมินเปิดดู (เช่นเรื่องที่แจ้งเข้ามาในระบบแจ้งปัญหา) ถ้าลืม escape สคริปต์จะรันในเบราว์เซอร์ของคนที่มีสิทธิ์สูงสุด (stored XSS) · นี่คือช่องโหว่ที่มักถูกมองข้ามเพราะคิดว่า "หน้าแอดมินอยู่ข้างใน ปลอดภัยแล้ว"
- ห้ามใส่ค่าจากผู้ใช้ลงใน `<script>` หรือ attribute ของ event (`onclick` ฯลฯ) โดยตรง
- **ข้อความที่ผ่าน `__()` ไม่ต้อง escape ซ้ำ** เพราะไฟล์ภาษาห้ามมีแท็ก HTML และ helper escape ค่าที่แทนใน placeholder ให้แล้ว — **แต่ข้อมูลจากฐานข้อมูลที่ไม่ได้ผ่าน `__()` ยังต้อง escape ตามปกติ**
- SVG ที่ผู้ใช้อัปโหลดถือเป็นไฟล์ที่รันสคริปต์ได้ **ห้ามเสิร์ฟ SVG จากผู้ใช้เป็น `image/svg+xml` โดยตรง**

## 6. CSRF

ทุกฟอร์มที่ทำ **POST / PUT / PATCH / DELETE** ต้องมี CSRF token ผูกกับ session และตรวจก่อนประมวลผลเสมอ

- สร้าง token ด้วย `bin2hex(random_bytes(32))` เก็บใน `$_SESSION`
- **เทียบด้วย `hash_equals()` ไม่ใช่ `==`** เพื่อป้องกัน timing attack
- เสริมได้ด้วยการตรวจ `Origin`/`Referer` เทียบ allowlist ควบคู่กับ token

---

## 7. Session

- ตั้ง `session.cookie_httponly = 1` · `session.cookie_samesite = Lax` · `session.cookie_secure = 1` (production)
- **เรียก `session_regenerate_id(true)` ทุกครั้งหลัง login สำเร็จ** เพื่อกัน session fixation
- ล้าง session ให้หมดจริงตอน logout ไม่ใช่แค่ลบบางคีย์
- กำหนดอายุ session และเวลาไม่มีการใช้งาน (idle timeout) ให้เหมาะกับความอ่อนไหวของข้อมูล

---

## 8. Input Validation

**ห้ามเชื่อ `$_POST` / `$_GET` / `$_FILES` ตรงๆ** ต้อง validate ชนิด รูปแบบ และขอบเขตก่อนใช้งานเสมอ

- ค่าที่มีตัวเลือกจำกัด (status, type, role) ต้องตรวจว่าอยู่ในชุดที่กำหนดเท่านั้น
- ‼️ **ค่าที่ถูกนำไปใช้เลือกไฟล์ต้องเทียบ allowlist ก่อนเสมอ ห้ามนำไปประกอบเป็น path ตรงๆ** — `?lang=` ต้องอยู่ในรายการภาษาที่เปิดใช้ และ slug คู่มือต้องมีอยู่ในทะเบียน `config/manuals.php` · ถ้าเชื่อค่าดิบจะกลายเป็นช่องอ่านไฟล์นอกโฟลเดอร์ (path traversal) ทันที
- ค่าที่เป็น id ต้องตรวจว่าเป็นตัวเลขและ**ผู้ใช้คนนั้นมีสิทธิ์เข้าถึงแถวนั้นจริง**
- **ต้องมี rate limit** ในจุดที่คนนอกยิงเข้ามาได้ — login, ฟอร์มแจ้งปัญหา, ฟอร์มสาธารณะทุกตัว · เก็บความพยายามลงตาราง `login_attempts` แล้วบล็อกตาม IP + บัญชี

## 9. File Upload

- **ตรวจ mime type จริงด้วย `finfo_file()`** ห้ามเชื่อ `$_FILES['type']` ที่ client ส่งมาเพราะปลอมได้
- ตรวจนามสกุลกับ mime ให้สอดคล้องกัน และใช้ **allowlist** ไม่ใช่ blocklist
- ตรวจขนาดไฟล์ก่อนเสมอ ทั้งฝั่ง PHP config และในโค้ด
- **สุ่มชื่อไฟล์ใหม่ตอนบันทึก** ห้ามใช้ชื่อที่ผู้ใช้ส่งมาตรงๆ (เก็บชื่อเดิมไว้ในฐานข้อมูลเพื่อแสดงผล)
- **เก็บไฟล์นอก `public/`** แล้วเสิร์ฟผ่าน Controller ที่ตรวจสิทธิ์ก่อนเสมอ
- Controller ที่เสิร์ฟไฟล์ต้อง**หา path จาก id ในฐานข้อมูล ไม่ใช่รับ path จาก query string**
- ส่งไฟล์ด้วย `Content-Disposition: attachment` และ `X-Content-Type-Options: nosniff` เว้นแต่จำเป็นต้องแสดงในหน้า

## 10. ส่งออก CSV

มาตรฐานนี้บังคับให้หน้ารายงานมีปุ่มส่งออก CSV จึงเกิดช่องโหว่ที่คนไม่ค่อยรู้จัก

‼️ **CSV injection** — ค่าที่ขึ้นต้นด้วย `=` `+` `-` `@` `\t` `\r` จะถูก Excel และ Google Sheets ตีความเป็นสูตร ทำให้ข้อมูลที่ผู้ใช้กรอกเข้ามากลายเป็นคำสั่งที่รันบนเครื่องคนเปิดไฟล์

- ต้อง**เติม `'` นำหน้าค่าที่ขึ้นต้นด้วยอักขระเหล่านั้น** ก่อนเขียนลงไฟล์
- ส่งออกเฉพาะคอลัมน์และแถวที่**ผู้ใช้คนนั้นมีสิทธิ์เห็น** ไม่ใช่ดึงทั้งตาราง
- ใส่ BOM `\xEF\xBB\xBF` ต้นไฟล์ ไม่งั้น Excel บน Windows อ่านภาษาไทยเป็นตัวขยะ

## 11. ‼️ Route migrate — ช่องทางที่มาตรฐานนี้สร้างขึ้นเอง

`GET /_migrate?token=...` ให้ CI สั่งรัน migration ได้โดยไม่ต้องมี SSH — **แปลว่ามีปลายทางที่แก้โครงสร้างฐานข้อมูลได้เปิดอยู่บนอินเทอร์เน็ต** ต้องปิดกั้นให้แน่นที่สุด

- token สุ่มยาวอย่างน้อย 32 ไบต์ เก็บใน `.env` และ **GitHub Secrets** เท่านั้น
- **เทียบด้วย `hash_equals()`** ไม่ใช่ `==`
- token ไม่ตรง → ตอบ **404 ไม่ใช่ 403** เพื่อไม่ให้รู้ว่ามี endpoint นี้อยู่
- **rate limit เข้มกว่าทุก endpoint** และบันทึกทุกครั้งที่ถูกเรียกลง log พร้อม IP ไม่ว่าจะสำเร็จหรือไม่
- ปิดการทำงานเมื่อ `APP_ENV` ไม่ใช่ค่าที่ตั้งใจ และ**ห้ามคืนรายละเอียด error ของฐานข้อมูลกลับไปใน response**
- รันได้เฉพาะ migration ที่ยังไม่เคยรัน — ห้ามรับพารามิเตอร์ว่าจะรันไฟล์ไหนจาก query string
- ‼️ **เปลี่ยน token ทันทีถ้ามันเคยหลุดเข้า log, commit, หรือ URL ที่แชร์ออกไป**

## 12. การตั้งค่าระดับระบบ

- **production ต้องปิด `display_errors`** error ทั้งหมดไปที่ log เท่านั้น
- **ห้าม hardcode credential ในโค้ดเด็ดขาด** ต้องอยู่ใน `.env` และ `.env` ต้องอยู่ใน `.gitignore`
- **บังคับ HTTPS บน production**
- document root ต้องชี้ที่ `public/` เท่านั้น — ชี้ผิดแล้ว `.env` โหลดได้จากเบราว์เซอร์ทันที
- `.htaccess` ต้องปิด directory listing และปิดการเข้าถึงไฟล์ที่ขึ้นต้นด้วยจุด

### Security headers — ตั้งที่ `core/Security.php` จุดเดียว

| Header | ค่า | กันอะไร |
|---|---|---|
| `X-Content-Type-Options` | `nosniff` | เบราว์เซอร์เดาชนิดไฟล์เองแล้วรันสิ่งที่ไม่ควรรัน |
| `X-Frame-Options` | `SAMEORIGIN` | ถูกฝังใน iframe เว็บอื่นเพื่อหลอกให้คลิก |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | URL ที่มีข้อมูลรั่วไปเว็บอื่น |
| `Content-Security-Policy` | อย่างน้อย `default-src 'self'` | XSS และการโหลดสคริปต์จากภายนอก |

> CSP ตั้งเข้มได้ง่ายในมาตรฐานนี้ เพราะเราไม่โหลดอะไรจาก CDN เลยอยู่แล้ว — **ห้าม `unsafe-inline`** ให้ย้าย inline script ไปไฟล์ JS แทน

## 13. ตรวจก่อนเปิด PR

ทุกครั้งที่แตะ auth, การรับ input, การอัปโหลด หรือฐานข้อมูล ต้องเรียก `/security-review` และผ่านรายการนี้

- [ ] ทุก query ใช้ prepared statement และค่าที่ผูก placeholder ไม่ได้ (sort, dir) ผ่าน allowlist แล้ว
- [ ] ทุก output ที่มาจากผู้ใช้ escape แล้ว **รวมหน้าแอดมิน**
- [ ] ทุกฟอร์มที่เปลี่ยนข้อมูลมี CSRF token และเทียบด้วย `hash_equals()`
- [ ] route ใหม่ทุกเส้นผูก Middleware ถูกต้อง และ**ทดสอบด้วยการเรียก URL ตรงด้วยผู้ใช้ที่ไม่มีสิทธิ์แล้ว**
- [ ] **ตรวจสิทธิ์ระดับแถวแล้ว** ไม่ใช่แค่ระดับหน้า
- [ ] แถวที่ถูก soft delete เข้าถึงไม่ได้จริง
- [ ] ไม่มี credential, token หรือรหัสผ่านหลุดลงโค้ด, log หรือ audit log
- [ ] จุดที่อัปโหลดไฟล์ตรวจ mime จริง ตรวจขนาด และสุ่มชื่อไฟล์ใหม่แล้ว
- [ ] Controller ที่เสิร์ฟไฟล์หา path จาก id ในฐานข้อมูล ไม่ใช่รับ path จาก URL
- [ ] ปุ่มส่งออก CSV กัน formula injection และส่งออกเฉพาะแถวที่ผู้ใช้มีสิทธิ์เห็น
- [ ] endpoint ที่คนนอกยิงได้มี rate limit
- [ ] `/_migrate` ตอบ 404 เมื่อ token ผิด และบันทึก log ทุกครั้งที่ถูกเรียก
- [ ] security headers ครบและ CSP ไม่มี `unsafe-inline`
- [ ] audit log บันทึกครบทุกจุดที่เปลี่ยนแปลงข้อมูลของงานชิ้นนี้
- [ ] ค่าที่ใช้เลือกไฟล์ (`?lang=`, slug คู่มือ) เทียบ allowlist แล้ว
