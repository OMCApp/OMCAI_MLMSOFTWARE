> ‼️ **ห้ามเขียนเลขเวอร์ชันซ้ำในไฟล์นี้** — ไฟล์นี้เคยเขียน `3.0.0` ค้างไว้ข้ามสองรุ่นโดยไม่มีใครเห็น
> เลขเวอร์ชันมีที่เดียวคือ `VERSION` ตามกฎ "ทุกอย่างเป็นของกลาง แก้ที่เดียวเปลี่ยนทั้งระบบ"

> ‼️ **โฟลเดอร์นี้ห้ามแก้ในโปรเจคเด็ดขาด**
> อยากแก้ต้องแก้ที่ repo มาตรฐานกลางแล้วปล่อยเวอร์ชันใหม่ — ไม่งั้นผ่านไป 3 เดือนแต่ละโปรเจคจะมีมาตรฐานคนละตัว แล้วกลับไปสู่ปัญหาที่ workflow นี้ตั้งใจแก้ตั้งแต่แรก
> `scripts/check.php` เทียบ hash ของโฟลเดอร์นี้ · `scripts/` · `CLAUDE.md` · `.claude/commands/` กับเวอร์ชันกลาง ถ้าไม่ตรงจะ fail — **`scripts/` เป็นของมาตรฐานด้วย ไม่ใช่แค่โฟลเดอร์นี้**

## หลักการที่อยู่เบื้องหลังทั้งชุด

**1. ทุกอย่างเป็นของกลาง แก้ที่เดียวเปลี่ยนทั้งระบบ**
อะไรที่ต้องไล่แก้หลายที่ ถือว่าออกแบบผิดตั้งแต่ต้น

**2. กฎที่แปลงเป็นสคริปต์ได้ ต้องแปลง**
ข้อความเป็นคำแนะนำ สคริปต์เป็นกำแพง — เก็บข้อความไว้เฉพาะสิ่งที่บังคับด้วยเครื่องไม่ได้

**3. ของที่เพิ่มทีหลังยากที่สุด ต้องทำตั้งแต่วันแรก**
audit log · i18n · design token · คู่มือ — ทั้งสี่อย่างทำวันแรกแทบไม่มีต้นทุน แต่ย้อนทำทีหลังต้องไล่แก้ทั้งระบบและมักเหลือค้าง

**4. artifact คือความจำ ไม่ใช่บทสนทนา**
แชทหาย ความคืบหน้าไม่หาย — session ใหม่หรือเพื่อนร่วมทีมอ่าน `project/` แล้วทำต่อได้ทันที

**5. ความไม่สม่ำเสมอเริ่มที่ input ไม่ได้เริ่มที่กฎ**
ชุดคำถามตายตัวใน `interview.md` สำคัญพอๆ กับกฎการเขียนโค้ด

## อัปเดตมาตรฐาน

```bash
php scripts/standard-update.php
```

**บอก Claude ว่า "อัปเดตมาตรฐาน"** — ขั้นตอนเต็มอยู่ที่ [`flow.md`](flow.md) ข้อ 14 · สั่งเองก็ได้ คำสั่งข้างบนดูอย่างเดียว เติม `--yes` เพื่อลงมือ

- **ดูก่อนเสมอ** — เวอร์ชันเก่า → ใหม่ · ⚠️ ระหว่างทาง · ไฟล์ที่จะเปลี่ยน · ขั้นอัปเกรด · สิ่งที่ต้องแก้ก่อน
- ทับเฉพาะของมาตรฐาน (`standard/` · `CLAUDE.md` · `scripts/` · `.claude/commands/`) · รวมค่า `.claude/settings.json` · **ไม่แตะ `project/` และโค้ดโปรเจค**
- ⚠️ ของแต่ละเวอร์ชันมาเป็นขั้นอัปเกรดใน `scripts/upgrades/` ที่แก้ให้ หรือบอกว่าต้องแก้ตรงไหน
- รันชุดตรวจเต็มให้เองหลังลงมือ

## ปล่อยเวอร์ชันใหม่ — ใน repo กลางเท่านั้น

1. แก้ `standard/VERSION` · บรรทัดแรกของ `CLAUDE.md` · หัวข้อบนสุดของ `CHANGELOG.md` ให้ตรงกัน แล้ว generate `AGENTS.md`
2. เวอร์ชันที่มี ⚠️ ต้องมี `scripts/upgrades/<เวอร์ชัน>.php` — รูปแบบอยู่ที่หัวไฟล์ `scripts/upgrades/3.9.0.php`
3. `php scripts/standard-update.php --seal` เป็นขั้นสุดท้าย — **ลายเซ็นที่ไม่ตรงคือโปรเจคทุกตัวที่อัปเดตจะ fail ทันที**
4. `php scripts/check.php` ผ่าน แล้ว merge เข้า `main`

## อยากเสนอแก้มาตรฐาน

**ห้ามแก้ในโปรเจค** ให้ทำแบบนี้แทน

1. บันทึกสิ่งที่เจอลง **`project/FEEDBACK.md`** พร้อมเหตุผล ตัวอย่างจริงที่ทำให้ติด และ **คำตอบว่าตรวจด้วยเครื่องได้ไหม**
2. ถ้าเป็นเรื่องเร่งด่วนและต้องเบี่ยงเบนก่อน ให้บันทึกไว้ที่ `project/NOTES.md` ว่าโปรเจคนี้ต่างจากมาตรฐานตรงไหนเพราะอะไร
3. เอาไปเปิดเป็น issue หรือ PR ที่ repo มาตรฐานกลาง

> **กฎที่ดีที่สุดมาจากความเจ็บจริงในโปรเจค ไม่ได้มาจากการนั่งคิดในห้อง** — ถ้าเจอว่ากฎไหนใช้ไม่ได้จริง นั่นคือข้อมูลที่มีค่าที่สุดของชุดมาตรฐานนี้
