# Skills ที่ต้องมีก่อนเริ่มงาน

> อ่านครั้งแรกที่ทำงานในโปรเจคนี้บนเครื่องใหม่
> **ถ้า skill กลุ่มบังคับไม่ครบ ให้หยุดแล้วบอกผู้ใช้ก่อน ห้ามเริ่มงานจริง**

---

## 1. ทำไมต้องมีไฟล์นี้

skill คือชุดความสามารถเพิ่มเติมของ Claude Code ที่ติดตั้งแยกต่อเครื่อง **ไม่ติดมากับการ clone โปรเจค**

แปลว่าเพื่อนร่วมทีมที่ clone โปรเจคเดียวกันแต่ไม่ได้ติดตั้ง skill ชุดเดียวกัน **จะได้ผลงานคนละมาตรฐาน** ทั้งที่ใช้ `standard/` ชุดเดียวกัน — นั่นคือปัญหาความไม่สม่ำเสมอที่ workflow นี้ตั้งใจจะแก้ตั้งแต่แรก

---

## 2. ตรวจว่ามีอะไรแล้วบ้าง

`php scripts/setup.php` ตรวจให้อยู่แล้วในขั้น A0 และบอกชัดว่าขาดตัวไหนพร้อมคำสั่งติดตั้ง — **ปกติไม่ต้องตรวจเอง**

ถ้าอยากดูเองก็อ่าน `~/.claude/settings.json` ที่คีย์ `enabledPlugins`

```bash
cat ~/.claude/settings.json
```

ตัวอย่างเครื่องที่ติดตั้งครบ

```json
"enabledPlugins": {
  "frontend-design@claude-plugins-official": true,
  "superpowers@claude-plugins-official": true,
  "security-guidance@claude-plugins-official": true,
  "ui-ux-pro-max@ui-ux-pro-max-skill": true,
  "impeccable@impeccable": true
}
```

## 4ก. ‼️ MCP — คนละเรื่องกับ plugin และไฟล์นี้เคยไม่พูดถึงเลย

**MCP คือเครื่องมือภายนอกที่ AI เรียกใช้ได้** ต่อไว้ต่อบัญชี/ต่อเครื่อง **ไม่ติดมากับการ clone** เหมือนกับ plugin ทุกประการ

> ‼️ **ไฟล์นี้มีอยู่เพื่อเรื่องนี้โดยตรง แต่เคยครอบคลุมแค่ plugin** — มาตรฐานพึ่งเครื่องมือสร้างภาพมาตั้งแต่ 3.7.0 โดยไม่เคยบอกว่าตัวไหน หรือทำยังไงถ้าไม่มี
> `grep higgsfield standard/` เคยได้ **0 บรรทัด** ทั้งที่ `design.md` 7ก.3ข เขียนว่าเส้นทาง ก ใช้ "MCP สร้างภาพ"

### เครื่องมือสร้างภาพ — **Higgsfield**

| | |
|---|---|
| **สถานะ** | **แนะนำ ไม่บังคับ** — ต่างจาก plugin เพราะ**มีค่าใช้จ่าย** คนในทีมอาจไม่มีด้วยเหตุผลที่ชอบธรรม |
| **ใช้ตอนไหน** | เส้นทาง ก — ช่วง C ตอนประกอบหน้าสาธารณะ · เส้นทาง ข — **Claude Design เรียกเอง**ตอนออกแบบ |
| **ไม่มีแล้วเป็นยังไง** | ระบบยังทำงานครบทุกอย่าง แต่**หน้าสาธารณะจะไม่มีภาพ** ซึ่ง `design.md` 7ก บอกเองว่า *"ดูไม่ดีไม่ว่าดีไซน์จะแม่นแค่ไหน"* → เดินทางสำรองตาม [`design.md`](design.md) 7ก.3ค |
| **ต่อยังไง** | ต่อผ่านตัวเชื่อม (connector) ของบัญชี Claude — **ผู้ใช้ต้องทำเอง AI ทำแทนไม่ได้** เหมือนกับ `/plugin install` |

### ‼️ ต้องเตือนผู้ใช้ ไม่ใช่รอให้เขาไปเจอเอง

**สคริปต์ตรวจ MCP แบบเดียวกับ plugin ไม่ได้** — plugin อ่านได้จาก `~/.claude/settings.json` คีย์ `enabledPlugins` แต่ตัวเชื่อมของบัญชีไม่ได้อยู่ในไฟล์ที่ `setup.php` อ่านได้
`setup.php` จึงไม่มีทางรู้ และกฎ *"ไม่ครบต้องหยุดรอ"* ของขั้น A0 ใช้กับเรื่องนี้ไม่ได้

**คนที่รู้คือ AI เอง เพราะมันเห็นเครื่องมือที่ตัวเองมีในมือ** — หน้าที่จึงเป็นของ AI ไม่ใช่ของสคริปต์

| ตอนไหน | ต้องทำอะไร |
|---|---|
| **ช่วง A ข้อ 7ข** | ถามว่าจะใช้ภาพที่สร้างขึ้นไหม · ตอบว่าใช้ → **ตรวจว่าตัวเองมีเครื่องมือสร้างภาพหรือยัง** |
| **ไม่มี** | **เตือนผู้ใช้ทันทีให้ต่อ Higgsfield MCP** พร้อมบอกว่าถ้าไม่ต่อจะได้อะไรแทน — **ห้ามเงียบแล้วไปเจอตอนช่วง C** ซึ่งตอนนั้นออกแบบหน้าไปแล้วโดยสมมติว่ามีภาพ |
| **เส้นทาง ข ขั้น B4** | เตือนซ้ำก่อนส่ง brief เพราะ **Claude Design ต้องมีเครื่องมือของฝั่งเขาเอง** ไม่ได้ใช้ของฝั่งเรา |

> ‼️ **เตือนแล้วผู้ใช้บอกว่าไม่ต่อ ก็ทำงานต่อได้** — บันทึกลง `project/NOTES.md` ว่าโปรเจคนี้ทำโดยไม่มีเครื่องมือสร้างภาพ เพื่อให้คนที่มารับช่วงรู้ว่าทำไมหน้าถึงเป็นแบบนั้น
> เหมือนกับกรณี plugin กลุ่มบังคับที่ผู้ใช้ยืนยันว่าให้ข้าม (ข้อ 8)

## 5. วิธีติดตั้ง

> ‼️ **นี่คือขั้นเดียวในการตั้งค่าทั้งหมดที่ AI ทำแทนไม่ได้**
> `/plugin` เปิดหน้าต่างเลือกแบบโต้ตอบ และหลังติดตั้งต้องเปิด session ใหม่ ซึ่ง AI สั่งเองไม่ได้
> จึงต้องทำ**ก่อน**คุยเรื่องงาน — ทำทีหลังแปลว่าบทสนทนาที่เก็บความต้องการไว้หายหมด

รันใน **เทอร์มินัล `claude` แบบโต้ตอบ** (คำสั่ง `/plugin` เปิดหน้าต่างเลือก จึงใช้ในโหมดอื่นไม่ได้)

เพิ่ม marketplace ที่ไม่ใช่ของทางการก่อน

```bash
/plugin marketplace add nextlevelbuilder/ui-ux-pro-max-skill
```

```bash
/plugin marketplace add pbakaus/impeccable
```

แล้วติดตั้ง

```bash
/plugin install superpowers@claude-plugins-official
```

```bash
/plugin install security-guidance@claude-plugins-official
```

```bash
/plugin install frontend-design@claude-plugins-official
```

```bash
/plugin install impeccable@impeccable
```

```bash
/plugin install ui-ux-pro-max@ui-ux-pro-max-skill
```

ติดตั้งเสร็จต้องเปิด session ใหม่ถึงจะใช้ได้

## 6. ‼️ ลำดับความสำคัญเมื่อ skill ขัดกับมาตรฐาน

**ข้อสำคัญที่สุดของไฟล์นี้**

skill แต่ละตัวมีปรัชญาการทำงานและคลังสไตล์ของตัวเอง ถ้าปล่อยให้มันนำ มันจะแย่งบทบาทกับ `standard/` แล้วผลงานจะกลับไปไม่สม่ำเสมออีก

**ลำดับที่ต้องยึด:** คำสั่งผู้ใช้ → `CLAUDE.md` → `standard/` + `project/` → skill → ค่า default ของ AI

| สถานการณ์ | ทำยังไง |
|---|---|
| skill เสนอสี ฟอนต์ หรือ radius ที่ต่างจาก `project/DESIGN.md` | **ยึด `DESIGN.md` เสมอ** ถ้าคิดว่าข้อเสนอดีกว่าจริง ให้บันทึกลง `project/QUESTIONS.md` แล้วถามผู้ใช้ที่ประตูถัดไป — ห้ามเปลี่ยนเอง |
| skill เสนอ flow การทำงานของตัวเอง (เช่น brainstorm → plan → execute) | **ยึด `standard/flow.md`** — flow ของโปรเจคนี้คือ `/wf` ช่วง A-E เท่านั้น ใช้ความสามารถของ skill ได้ แต่ไม่เปลี่ยนลำดับงาน |
| skill เสนอให้ใช้ framework, library หรือ CDN | **ปฏิเสธ** — กฎเหล็กข้อ 2 ใน `CLAUDE.md` ห้ามเพิ่ม dependency โดยไม่ถามผู้ใช้ และห้าม CDN |
| skill เสนอโครงสร้างโฟลเดอร์หรือ pattern โค้ดที่ต่างจาก `rule.md` | **ยึด `rule.md`** |
| skill ชี้ปัญหาด้านคุณภาพ a11y หรือความปลอดภัย | **รับฟังและแก้** — นี่คือสิ่งที่เราติดตั้ง skill มาเพื่อให้ได้ |

หลักสั้นๆ: **ให้ skill ช่วยเรื่องคุณภาพ ไม่ให้ skill ตัดสินใจแทนมาตรฐาน**

## 8. ถ้าไม่ครบต้องทำยังไง

1. บอกผู้ใช้ว่า**ขาดตัวไหน** และ**ตัวนั้นทำอะไร**
2. ถ้าขาดกลุ่มบังคับ — **หยุดรอ ห้ามเริ่มงานจริง** เพราะงานที่ออกมาจะไม่อยู่ในมาตรฐานเดียวกับที่ทีมตั้งใจ
3. ถ้าขาดเฉพาะกลุ่มแนะนำ — แจ้งแล้วทำงานต่อได้
4. ถ้าผู้ใช้ยืนยันว่าให้ข้ามทั้งที่ขาดกลุ่มบังคับ — ทำต่อได้ แต่ต้องบันทึกไว้ใน `project/NOTES.md` ว่าโปรเจคนี้ทำโดยไม่มี skill ตัวไหนบ้าง เพื่อให้คนที่มารับช่วงรู้
