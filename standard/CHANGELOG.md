## 3.20.0 (2026-10-12)

> ที่มา: **ทุกโปรเจคที่ใช้มาตรฐาน** ได้ checkbox · radio · select สีฟ้าของ Windows เพราะไม่มีสไตล์ของสามอย่างนี้ใน `app.css` เลย
> กฎ "control ที่กางอะไรออกมาเมื่อกด ต้องปั้นใหม่" มีมาตั้งแต่ 3.2.0 — **แต่ไม่เคยมีของจริงในโครงรองรับ จึงไม่มีใครทำ**

### ทำให้จริงในโครง

| อะไร | เดิม | ตอนนี้ |
|---|---|---|
| `select` | กล่องและรายการของ OS ทั้งคู่ | `app.js` ครอบ **ทุกตัว** เป็น listbox ของระบบ · ลูกศรวาดเอง · ช่องค้นโผล่เฉพาะเกิน 8 ตัวเลือก (ข้อ 3ก) · หน้าที่ต้องการของ OS จริงๆ ใส่ `data-native` |
| checkbox · radio | กล่องสีฟ้าของ OS ไม่ตามธีมและโหมดมืด | วาดเองด้วย `appearance: none` + `clip-path` · สีจาก token · มีสถานะครึ่งๆ กลางๆ · ทั้งแถวกดได้สูง 44px |
| `field.php` | ไม่รองรับ checkbox/radio เลย ต้องเขียน markup เองทุกหน้า | `$fieldType = 'checkbox' / 'radio' / 'checkboxes'` · กลุ่มตัวเลือกออกมาเป็น `fieldset` + `legend` |

ขนาดของกล่องติ๊ก เครื่องหมาย และลูกศร เป็น token ใน `DESIGN.md` (`component.choice`) ไม่ใช่ค่าดิบใน CSS

### ตัวตรวจที่ทำให้มันไม่หายอีก

`design/native-control-styled` — `app.css` ต้องมีสไตล์ของ checkbox · radio · รายการ dropdown และ `app.js` ต้องครอบ `select` จริง
**บทเรียนเดียวกับ 3.18.0: กฎที่ไม่มีตัวตรวจรองรับจะถูกข้ามเสมอ**

### บั๊กที่เจอระหว่างทดสอบ

- `select` ที่ค่าเป็นค่าว่าง (ตัวเลือก "ไม่ระบุ") แสดงช่องเปล่า เพราะโค้ดเช็ค `value === ''` แล้วไม่แสดงอะไร — ต้องอ่านป้ายของ option ที่ถูกเลือกเสมอ
- ตัวสลับภาษาบนแถบบนกว้างขึ้นเป็น 214px เพราะ `.combobox` ยืดเต็มที่ว่าง — นอกฟอร์มต้องกว้างตามตัวเลือกที่ยาวที่สุด

ทดสอบ: ทั้งสามอย่างในเบราว์เซอร์จริง โหมดสว่างและมืด · คีย์บอร์ดเลือกค่าได้ · **ตัวสลับภาษายังเปลี่ยนภาษาได้จริงหลังถูกครอบ**

### ⚠️ โปรเจคที่ใช้เวอร์ชันเก่า

`app.css` · `app.js` · `field.php` · `DESIGN.md` อยู่ในส่วนที่โปรเจคแก้เองได้ ตัวอัปเดตจึงไม่ทับ — ขั้นอัปเกรด `3.20.0.php` บอกทีละข้อว่าต้องรวมอะไร
**หน้าที่เคยเขียน `<input type="checkbox">` เองไว้ในหน้า ต้องย้ายมาใช้ `field.php`** ไม่งั้นมันจะยังเป็นกล่องของ OS อยู่ (ขั้นอัปเกรดไล่หาให้)

## 3.19.0 (2026-09-29)

> ที่มา: ทีมที่ใช้จริงส่งข้อเสนอมาว่า dropdown ควรมีเกณฑ์กลาง ไม่ใช่ตัดสินทีละหน้า — และบางหน้าโหลด master data ทั้งตารางลงหน้าเว็บอยู่แล้ว
> มาตรฐานมีกฎว่า "dropdown ของ OS ต้องปั้นใหม่" มาตั้งแต่ 3.2.0 แต่**ไม่เคยมีตัว component จริงในโครง** ทุกโปรเจคจึงต้องเขียนเองและได้คนละแบบ

### เกณฑ์กลาง — `components.md` ข้อ 3ก

| จำนวนรายการ | ต้องทำ |
|---|---|
| 1–8 | `<select>` ปกติ |
| 9–50 | ค้นได้ โหลดครั้งเดียวแล้วกรองฝั่งหน้าเว็บ |
| เกิน 50 | ค้นจากฝั่ง server ห้ามโหลดทั้งหมดลงหน้า |

master data ที่โตขึ้นเรื่อยๆ (ผู้ใช้ ลูกค้า สินค้า สาขา) **ถือว่าเกิน 50 ตั้งแต่วันแรก** — วันที่ข้อมูลโต ไม่มีใครกลับมาแก้หน้าที่เขียนไว้ตอนมี 20 แถว
ฝั่ง server: เริ่มค้นที่ **2 ตัวอักษร** · **25 รายการต่อครั้ง** (เพดาน 50) · หน่วง **250ms** ก่อนยิง · ปุ่ม "ดูเพิ่ม" ท้ายรายการ

### ของจริงในโครง — ไม่ต้องเขียน component เอง

- `field.php` รับ `$fieldSearch` และ `$fieldSource` · **ไม่ระบุอะไรเลย เกิน 8 ตัวเลือกก็เปิดช่องค้นให้เอง**
- combobox เขียนเองใน `app.js` ไม่เพิ่ม dependency (ผู้ใช้เลือกทางนี้) — ARIA `combobox`/`listbox`/`aria-activedescendant` ครบ · `↑` `↓` `Home` `End` `Enter` `Esc` · กันผลของคำค้นเก่ามาทับคำค้นใหม่
- `config/options.php` เป็นทะเบียนแหล่งข้อมูลที่เดียว — ตาราง คอลัมน์ที่ค้นได้ เงื่อนไขตายตัว และสิทธิ์ · เพิ่มแหล่งใหม่ = เพิ่มรายการ ไม่ใช่เขียน endpoint ใหม่
- `GET /options/{key}` + `Option` / `OptionService` / `OptionAccessMiddleware`

### ความปลอดภัยของ dropdown ที่ค้นได้ — `security.md` ข้อ 4ก

- **สิทธิ์ของแหล่งข้อมูลบังคับที่ middleware ที่เดียว** (กฎเหล็กข้อ 4) — การค้นคือการอ่านข้อมูล ไม่ใช่แค่ช่วยกรอกฟอร์ม · แหล่งที่เปิดกว้างเกินไปคือการให้ไล่อ่านรายชื่อทั้งตารางทีละตัวอักษร
- **ค่าที่ฟอร์มส่งกลับมาต้อง validate ซ้ำด้วย `OptionService::allows()` เสมอ** — `<option>` ถูกเติมด้วย JS ตอนใช้งาน รายการที่หน้าเว็บเคยเห็นจึงไม่ใช่ขอบเขตของค่าที่ส่งกลับมาได้
- ชื่อตารางและคอลัมน์มีด่านตรวจใน `Option` เอง ไม่เชื่อว่า config ถูกเสมอ · คำค้น escape `%` `_` ด้วย `ESCAPE '!'`
- `structure/option-source-exists` จับคีย์ที่ไม่มีในทะเบียน — พิมพ์ผิดแล้ว dropdown ขึ้นปกติ แต่ผู้ใช้กดค้นได้ 404 เงียบๆ

### บั๊กที่เจอระหว่างทดสอบ

- **`ESCAPE '\\'` ใช้ไม่ได้ทุกฐานข้อมูล** — MySQL ถอด `\` ในสตริงให้อีกชั้นจึงเหลือตัวเดียว แต่ SQLite ได้สองตัวแล้วฟ้อง "ESCAPE expression must be a single character" · เปลี่ยนไปใช้ `!`
- **ห้ามซ่อน `<select>` ด้วย `display:none`** — `required` ที่ซ่อนแบบนั้นทำให้ฟอร์มส่งไม่ได้โดยไม่มีข้อความให้ผู้ใช้เห็น · โครงจึงวาง select ไว้แบบโปร่งใสและยังโฟกัสได้ พร้อมส่งโฟกัสต่อให้ช่องค้น

### ⚠️ โปรเจคที่ใช้เวอร์ชันเก่า

`field.php` · `app.js` · `app.css` · `lang/` · `config/options.php` อยู่ในส่วนที่โปรเจคแก้เองได้ ตัวอัปเดตจึงไม่ทับ
ขั้นอัปเกรด `3.19.0.php` คัดลอกไฟล์ใหม่ (`config/options.php` · Model · Service · middleware · Controller) ให้ และบอกทีละข้อว่าต้องรวมอะไรเอง — รวมถึง **route `/options/{key}` ที่ต้องเพิ่มเอง**
**dropdown เดิมที่มีเกิน 8 รายการยังเป็น select ธรรมดาจนกว่าจะผ่าน `field.php` รุ่นใหม่** — ไล่ดูหน้าที่มี dropdown ยาวหลังอัปเดต

## 3.18.0 (2026-09-25)

> ที่มา: ทีมใช้โหมดเร็วกับงานจริงแล้วรายงานว่า *"เร็วขึ้นจริงแต่คุณภาพของดีไซน์ลดลงอย่างเห็นได้ชัด · ไม่ตรงกับที่ออกแบบใน wireframe เลย บางอย่างก็หาย"*
> **เรื่องของดีไซน์ห้ามข้าม** — โหมดเร็วรอบแรก (3.16.0) เลื่อน `testing.md` ข้อ 2.2 ไปช่วง D ด้วย ซึ่งแปลว่าไม่มีใครเอาหน้าจริงไปวางเทียบกับแบบเลยตลอด phase

### ทำไมการเลื่อนข้อ 2.2 ถึงแพงกว่าข้ออื่น

| ข้อที่เลื่อน | ตอนเลื่อนแล้วเกิดอะไร |
|---|---|
| ทางผิดพลาด · สิทธิ์ · audit log (2.3–2.8) | บั๊กยังอยู่ให้เจอที่ช่วง D และมักแก้ที่ต้นเหตุครั้งเดียวได้ |
| **หน้าตา (2.2)** | **บล็อกที่หายไปจากแบบไม่มีอะไรฟ้อง** — หน้าที่ขาดบล็อกก็ยังดูเรียบร้อยเมื่อไม่มีอะไรวางเทียบ · และดีไซน์ที่เพี้ยนถูกลอกต่อทุก phase เหมือน pattern |

การตรวจดีไซน์ยังเป็น**งานของคนทำตอนจบ phase** ไม่ใช่ของผู้ใช้ที่รอที่ประตู — ตัดประตูย่อยออกจึงไม่ควรตัดการตรวจนี้ไปด้วย

### โหมดเร็วใหม่ — เลื่อนเฉพาะการตรวจที่ไม่ใช่ดีไซน์

**ไม่เลื่อนแล้ว (ทำทุก phase เหมือนโหมดปกติ):** `testing.md` ข้อ 2.2 ทั้งหมด · ภาพ 2 โหมด × 2 ความกว้าง และ component ที่ต้องกดก่อนเห็น (4ก) · เทียบกับภาพแบบ (4ข) · skill `impeccable`
**เพิ่มเป็นขั้นที่ต้องทำ:** เปิดแบบที่อนุมัติแล้ววางคู่กับหน้าจริง **ไล่ทีละบล็อก** — ของที่หายหรือไม่ตรงต้องแก้ใน phase นั้น ห้ามจดไว้ตรวจทีหลัง
**ยังเลื่อนไปช่วง D:** ข้อ 2.3–2.8 (ทางปกติ · ทางผิดพลาด · สิทธิ์ · audit log · ข้อมูลจริง · ภาษาและคู่มือ) และการรอผู้ใช้ตรวจ

ข้อแลกที่บอกผู้ใช้ตอนเลือกโหมดเปลี่ยนตาม — สิ่งที่จะไปรู้ตอนท้ายคือ**ฟังก์ชัน สิทธิ์ และข้อความ** ไม่ใช่หน้าตา

### `PLAN.md` แยก C4 เป็นสองขั้น

```markdown
## Phase 2 — จัดการคิว  🔨
- [x] C4ก ดีไซน์ — เทียบกับแบบแล้ว (โหมดเร็ว)
- [-] C4ข ทดสอบที่เหลือ — เลื่อนไปช่วง D (โหมดเร็ว)
```

`docs/fast-mode-debt` ขึ้น error ถ้า `C4ข` เป็น `[-]` โดยที่ `C4ก` ยังไม่ติ๊ก — **กฎที่ไม่มีตัวตรวจรองรับถูกข้ามเสมอ ซึ่งคือสิ่งที่เพิ่งเกิด**

### บั๊กที่เจอระหว่างทำ

`ProjectDocs::phases()` ใช้ `/^C[1-5]\b/u` หาขั้นตอนใน `PLAN.md` — PCRE โหมด `/u` นับตัวอักษรไทยเป็นตัวอักษรคำ ทำให้ `C4ก` ไม่เข้าเงื่อนไขและถูกนับเป็นรายการครบลูปแทน
ถ้าไม่เจอ กฎใหม่จะ "ผ่าน" ทุกกรณีโดยไม่ตรวจอะไรเลย · เปลี่ยน `\b` เป็น negative lookahead ของตัวเลขแทน

### ⚠️ โปรเจคที่ใช้เวอร์ชันเก่า

`PLAN.md` ที่ยังเขียน `- [-] C4 ทดสอบ — เลื่อนไปช่วง D (โหมดเร็ว)` จะขึ้น error ทันทีที่อัปเดต เพราะไม่มีบรรทัดที่ยืนยันว่าตรวจดีไซน์แล้ว
**นี่ไม่ใช่เรื่องรูปแบบ** — โปรเจคเหล่านั้นคือโปรเจคที่ยังไม่ได้เทียบหน้ากับแบบจริงๆ · ขั้นอัปเกรด `3.18.0.php` ไล่หา phase ที่ค้างแล้วบอกทีละ phase ว่าต้องเทียบก่อนจึงติ๊ก `C4ก`

## 3.17.0 (2026-09-21)

> ที่มา: ผู้ใช้ออกแบบหน้า login มาเป็นภาพ บอกว่าต้องเป็นแบบนี้ 100% แต่หน้าที่ได้ไม่เหมือนภาพ
> AI ในโปรเจคนั้นอธิบายเองว่า *"ไม่เคยเห็นภาพนี้ตอนสร้างหน้า และกฎบางข้อขัดกับภาพตรงๆ"*
> วิธีทำงานของผู้ใช้: ออกแบบทีละหน้า บันทึกเป็นภาพรวมในโฟลเดอร์ ส่ง path ให้ AI ใช้เป็นแบบ · สร้างภาพไม่ได้ก็ตัดจากภาพแบบมาใช้

### ต้นเหตุ 3 ข้อ

| ต้นเหตุ | อาการ |
|---|---|
| **ภาพแบบไม่มีที่อยู่ในระบบ** — มาตรฐานรู้จักแบบแค่ wireframe กับไฟล์จาก Claude Design | ภาพที่ส่งในแชทหายไปพร้อมบทสนทนา · C1 สั่งให้เปิด "แบบที่อนุมัติแล้ว" แต่ภาพนี้ไม่นับเป็นแบบ |
| **ไม่มีกฎว่าอะไรชนะเมื่อแบบขัดกับกฎจัดหน้า** — มีแค่ "กฎการเข้าถึงชนะดีไซน์" | ข้อ 5.4 "หน้าเดียวคอลัมน์เดียว" ทับการ์ดสรุปด้านซ้าย · คอมเมนต์ในโค้ดที่ AI session ก่อนเขียนว่า "ห้ามภาพบนหัวเพจ" ถูกใช้เป็นกฎ |
| **ไม่มีขั้นเทียบหน้าจริงกับแบบ** — ข้อ 4ก ตัดสินภาพเทียบกับกฎคุณภาพ ไม่เคยเทียบกับแบบ | หน้าที่ผ่านทุกกฎแต่ไม่เหมือนแบบเลย ถือว่าเสร็จได้ |

และโครงไม่มีช่องที่แบบต้องการ: หัวเพจไม่มีช่องภาพ · ไม่มี partial breadcrumb (มีแค่ประโยคใน `components.md`) · ไม่มีหน้าแบบด้านข้างคู่เนื้อหาหลัก — AI จึงตัดทิ้งแทนการเพิ่ม

### เส้นทาง ค — ผู้ใช้ออกแบบเองเป็นภาพ

คำถามข้อ 14 มีตัวเลือกที่สาม *"มีแบบของตัวเองแล้ว"* · ไม่ทำ wireframe · ถามต่อ 4 ข้อ (path ของโฟลเดอร์ · ชื่อฟอนต์ · หน้าไหนตรงแบบ/แนวทาง · มีภาพประกอบ export แยกไหม)

- `php scripts/design-refs.php --import <โฟลเดอร์>` คัดลอกเข้า `project/design/refs/` — **path ในเครื่องผู้ใช้เปิดไม่ได้ใน session ถัดไป**

### ‼️ 1. ประตู B ส่งของให้คนที่นั่งอยู่ตรงหน้า แต่ลูกค้าไม่ได้นั่งอยู่ตรงนั้น

พอผู้ใช้ต้องเอาแผนและดีไซน์ไปให้หัวหน้าหรือลูกค้าตัดสิน เขาต้องมานั่งเล่าเองทั้งหมด เพราะ `project/*.md` เปิดได้เฉพาะคนที่ clone repo แล้ว
**ผลคือสิ่งที่คนตัดสินใจได้เห็น ไม่ใช่สิ่งที่เราทำ แต่เป็นสิ่งที่ผู้ใช้จำได้**

**ขั้น B6 ใหม่ — ทำเอกสารสรุปเป็น Artifact ก่อนเปิดประตู ทั้งสองเส้นทาง**

### ‼️ 2. ดีไซน์ที่ได้จาก Claude Design ไม่มี motion เลยสักตัว — เพราะ brief ไม่เคยขอ

แบบฟอร์ม token ขอแค่ `motion.duration` กับ `motion.easing` ซึ่งเป็น **ตัวเลขสองชุด ไม่ใช่การออกแบบ**
ได้ตัวเลขกลับมาแล้วยังไม่มีใครรู้ว่า *อะไรเคลื่อน ตอนไหน เคลื่อนยังไง* แล้ว C3 ก็ไปเดาเอาเองทีหลัง — ซึ่งเป็นตอนที่ผู้ออกแบบไม่อยู่แล้ว

> ‼️ **motion เป็นส่วนหนึ่งของบุคลิก ไม่ใช่ของแต่งท้ายงาน**
> ระบบเดียวกันที่ของเลื่อนขึ้นช้าๆ กับที่ของเด้งเข้ามาเร็ว **ให้ความรู้สึกคนละแบรนด์** ทั้งที่สีและฟอนต์เหมือนกันทุกตัว
> ปล่อยให้ตัดสินตอน C3 แปลว่ายกการตัดสินใจเรื่องบุคลิกไปให้คนที่กำลังไล่ checklist อยู่

`design-brief.md` เพิ่มหมวด **motion** ขอ 4 อย่าง — บุคลิกเป็นคำ · รายการว่าอะไรเคลื่อนบ้าง · ค่าที่มาจากบุคลิกนั้นจริง · ‼️ **ตัวอย่างที่เคลื่อนไหวได้จริงในไฟล์ที่ส่งกลับมา** เพราะอ่านจากตัวเลขแล้วจินตนาการไม่ออก

พร้อมส่งข้อจำกัดไปด้วยทุกครั้ง โดยเฉพาะ **`fill-mode: backwards`** — `both` เป็นค่าที่คนใช้กันทั่วไป และมันทำให้ dropdown ทุกตัวในระบบถูกทับ โดยมองไม่เห็นจนกว่าจะมี dropdown ตัวแรก

**C3 เปลี่ยนบทบาท** — จากคนตัดสินว่า motion ควรเป็นแบบไหน เป็นคนลงมือทำตามที่ตัดสินไว้แล้วในช่วง B · ไม่มีเขียนไว้ = ช่วง B ทำไม่ครบ ให้จดลง `QUESTIONS.md` **ห้ามตัดสินบุคลิกใหม่เงียบๆ**

เดิมเข้าใจว่ามันสร้างรูปไม่ได้ เพราะไฟล์ที่ได้กลับมาครั้งแรกเป็น `<image-slot>` เปล่าทั้ง 25 ช่อง

**ความจริงคือมันเรียก MCP สร้างรูปได้ แต่ brief ไม่เคยบอกมันว่าทำได้** จึงวางกล่องเปล่ามาให้ตามที่สเปคขอ

| | ผู้ออกแบบมีรูปตอนออกแบบ | ผู้ออกแบบได้กล่องเปล่า |
|---|---|---|
| ภาพในส่วนเปิด | **เต็มจอ** ประกอบกับพาดหัวเป็นภาพเดียว | **กิน 39% ของจอ** ในกรอบสี่เหลี่ยมข้างข้อความ |

> ‼️ **ผู้ออกแบบที่สร้างรูปเองจะสร้างรูปที่เข้ากับ layout ที่กำลังปั้นอยู่**
> ส่งรูปสำเร็จไปให้ เขาได้แค่ "รูปที่ต้องหาที่วาง" ซึ่งจบลงที่ภาพในกรอบสี่เหลี่ยมข้างข้อความเสมอ

`design-brief.md` เพิ่มหมวด **รูปภาพ** 4 อย่าง — บอกว่าเขาสร้างเองได้ · สัดส่วนของแต่ละที่ · ข้อห้ามเรื่องฉลาก · **ขอ manifest ของ URL เป็นข้อความ**

**ที่ต้องขอ manifest แยก** เพราะไฟล์ที่ได้กลับมาเป็น bundle ที่ `grep` ไม่ได้ (3.6.1 ข้อ 3) — ไม่ขอเป็นรายการ จะต้องไล่งัด URL ออกจาก DOM ทีละอัน

**และต้องส่งบทเรียนเรื่องฉลากไปด้วยทุกครั้ง** — สั่ง `no text, no labels` ไม่ได้ผล ทดสอบแล้วได้ฉลากมั่วกลับมา 4 จาก 5 ใบ · ไม่บอกไป เขาจะเจอปัญหาเดิมแล้วเราต้องมาแก้ทีหลัง

**ขั้น B6 ใหม่** — ดึงรูปจาก manifest ด้วย `fetch-image.php` ทีละใบ **ตามสัดส่วนที่สเปคกำหนด ไม่ใช่ตามที่ไฟล์ต้นทางเป็น** · ข้ามขั้นนี้แล้วให้หน้าอ้าง URL ตรงๆ คือโหลดจาก CDN ซึ่งกฎเหล็กข้อ 2 ห้าม และลิงก์มีวันหมดอายุ

### ‼️ 2. เส้นทาง ก บังคับเรียก skill ด้านดีไซน์ — เป็นขั้นตอน ไม่ใช่คำแนะนำ

`skills.md` เขียนไว้แล้วว่าให้ใช้ `frontend-design` ตอนตัดสิน `DESIGN.md` **แต่มันเป็นแถวในตาราง ไม่ใช่ขั้นตอนในงาน**

เทียบกับเรื่องอื่นที่มาตรฐานนี้เอาจริง — `design-sync.php` `check-contrast.php` `make-favicon.php` **ทุกตัวมีชื่อ มีลำดับ อยู่ในตารางของช่วง** ส่วนการเรียก skill ไม่เคยมีสถานะแบบนั้น จึงถูกข้ามเป็นปกติ

| ขั้นใหม่ | ทำอะไร |
|---|---|
| **B3ก** | เรียก `frontend-design` **ก่อนตัดสินอะไร** |
| **B4ก** | ให้ `impeccable` ตรวจ wireframe แล้วแก้ตามที่มันชี้ **ก่อนเข้าประตู B** |

> ‼️ **เส้นทาง ก คือเส้นทางที่ไม่มีใครช่วยเรื่องหน้าตาเลย** — ไม่มี Claude Design ไม่มีคนออกแบบ มีแต่ AI ที่กำลังไล่ checklist
> **และ AI ที่ไล่ checklist เลือกทางที่ปลอดภัยที่สุดเสมอ ซึ่งคือทางที่จืดที่สุด** (ดู `design.md` 5.16)
> skill ด้านดีไซน์คือสิ่งเดียวในเส้นทางนี้ที่ดันไปทางตรงข้าม — ข้ามมันแปลว่าเหลือแต่กฎความปลอดภัยล้วน

**`impeccable` ย้ายจากกลุ่มแนะนำเป็นกลุ่มบังคับ** ด้วยเหตุผลเดียวกัน

และให้บันทึกลง `DESIGN.md` ว่าใช้ skill ตัวไหนบ้าง เพื่อให้คนที่มารับช่วงรู้ว่าดีไซน์นี้ผ่านการตรวจอะไรมาแล้ว

> ‼️ **ข้อจำกัดที่ต้องรู้** — ไม่มีอะไรพิสูจน์ได้ว่า AI เรียก skill จริงหรือแค่เขียนบรรทัดนั้นลงไป
> เป็นกลไกแบบ "ประกาศสิ่งที่ทำ" เหมือน checkbox ซึ่งมาตรฐานนี้ยอมรับรูปแบบนี้อยู่แล้ว **แต่มันไม่ใช่กำแพงจริง**

### ‼️ 1. ปิดช่องว่างเรื่องรูปภาพ — `scripts/fetch-image.php`

หน้าสาธารณะที่ไม่มีภาพเลย **ดูไม่ดีไม่ว่าดีไซน์จะแม่นแค่ไหน** ภาพหนึ่งใบทำงานแทน layout ได้เกือบทั้งส่วน

แต่เครื่องมือสร้างภาพทุกเจ้า**คืน URL บนคลาวด์ ไม่ใช่ไฟล์ในโปรเจค** ปล่อยให้หน้าอ้าง URL นั้นตรงๆ คือโหลดจาก CDN ซึ่งกฎเหล็กข้อ 2 ห้าม และวันที่ลิงก์หมดอายุ **รูปหายทั้งเว็บโดยไม่มีใครรู้ล่วงหน้า**

```bash
php scripts/fetch-image.php --url "https://..." --out hero-bottle --ratio 3:4
```

ดาวน์โหลด ครอปตามสัดส่วนที่ `DESIGN.md` กำหนด ย่อ แปลง WebP จบในขั้นเดียว · **วัดจริง 4.2 MB เหลือ 90 KB**

ไฟล์ที่ได้จากเครื่องมือสร้างภาพหนัก 3-5 MB ซึ่งใช้บนหน้าเว็บไม่ได้ โดยเฉพาะเมื่อผู้ใช้เข้าจากเน็ตมือถือ

**พร้อมกฎ 4 ข้อใน `design.md` 7ก** — ภาพแบ่งสองกอง (ของจริงต้องมาจากลูกค้า · ประกอบสร้างได้) · ต้องดาวน์โหลดมาเก็บเสมอ · ของตกแต่งที่ไม่ใช่ภาพถ่ายต้องเป็น SVG/CSS · และคำถามใหม่ในช่วง A ว่า**รูปมาจากไหน**

> ‼️ **คำสั่ง "ห้ามมีตัวหนังสือ" ไม่ได้ผล** สั่ง `no text, no labels` ไปแล้วยังได้ฉลากมั่วกลับมา **4 จาก 5 ใบ** — `Jasmine Jea` · `Taie Pu—KA!` · `CHRNETI`
> เพราะขวดสินค้าในข้อมูลที่โมเดลเรียนมามีฉลากทุกใบ
> **ทางแก้ที่ทดสอบแล้วได้ผลคือครอปมาโครให้ไม่เห็นส่วนที่ฉลากอยู่**

### ‼️ 3. `hero` กับ `page-head` อยู่ร่วมกันไม่ได้ — และทำเป็นกลไก ไม่ใช่กฎ

ทั้งคู่วาด `<h1>` · มีสองตัวแปลว่า**ไม่มีตัวไหนเป็นหัวจริง** และ screen reader อ่านโครงหน้าผิด

กฎเดิมใน `page-head.php` เขียนว่า *"ทุกหน้าต้องมีหัวเพจ ห้ามเขียน `<h1>` เองทีละหน้า"* ซึ่งถูกสำหรับหน้าหลังบ้าน แต่หน้าสาธารณะเปิดด้วย hero ไม่ใช่แถบชื่อหน้า

**แก้ด้วยกลไก ไม่ใช่ด้วยการเขียนกฎเพิ่ม** — `hero.php` เรียก `hero_rendered(true)` แล้ว `page-head.php` เช็คเองว่าจะไม่วาดซ้ำ

> ‼️ **สิ่งที่ต้องจำคือสิ่งที่จะถูกลืม** — ทางแก้แรกคือให้ Controller ส่ง `pageTitle` ว่างมาเอง ซึ่งได้ผลแต่ต้องจำทุกหน้า
> ที่ทำได้เพราะ `Controller::render()` capture หน้าก่อน layout เสมอ hero จึงทำงานก่อน page-head เสมอ

### ‼️ 4. `config('ui.nav_style')` เป็น config ที่ไม่มีใครอ่าน

มีอยู่ใน `config.php` มาตลอด แต่**ไม่มีโค้ดบรรทัดไหนอ่านมันเลย** layout จึงวาด sidebar เสมอ

ผลคือโปรเจคที่ตอบ `header` ไว้ตั้งแต่ช่วง A **ได้ sidebar ของหลังบ้านมาครอบหน้าสาธารณะ** และไม่มีอะไรรายงานว่าผิด เพราะในสายตาชุดตรวจมันไม่ผิด — มันแค่ไม่ตรงกับสิ่งที่ผู้ใช้สั่งไว้

> ‼️ **config ที่ไม่มีใครอ่าน อันตรายกว่าไม่มี config เลย** เพราะมันทำให้ทุกคนเชื่อว่าตั้งค่าได้แล้ว
> ชนิดเดียวกับ `scripts/make-favicon.php` ที่ถูกอ้างถึงข้ามหลายเวอร์ชันโดยไม่มีไฟล์อยู่จริง (3.6.2 ข้อ 1)

layout กลางอ่าน `config('ui.nav_style')` แล้ว · `header` ได้แถบบนที่มีแบรนด์กับเมนูอยู่แถวเดียวกัน ไม่มีปุ่มพับเพราะไม่มีอะไรให้พับ · บนมือถือเมนูตกลงมาเป็นแถวที่สองพร้อมพื้นที่กด 44px ไม่ใช่ซ่อนหาย

**กฎใหม่ `design.md` 5.15** — เว็บสาธารณะใช้ `header` ทุกกรณี sidebar กินพื้นที่มือถือและไม่มีเว็บโชว์เจ้าไหนทำ

### เรื่องที่ต้องรู้ตอนเขียน CSS ของ layout

`@layer` ตัดสินก่อน specificity — เขียน `.shell[data-nav="header"] .nav` ไว้ใน `@layer layout` แล้ว**แพ้ `.nav` เปล่าๆ ใน `@layer components`** เพราะ components มาทีหลังในลำดับชั้น

เมนูจึงยังเรียงลงล่างทั้งที่สั่ง `flex-direction: row` ไปแล้ว · **ย้ายเข้า layer เดียวกับของที่จะทับถึงจะได้ผล**

### ‼️ 1. ค่าที่ผู้ออกแบบตอบว่า "ไม่ต้องใช้" ไม่ได้แปลว่าระบบไม่ใช้

ผู้ออกแบบเห็นแค่หน้าที่อยู่ในสเปค แต่ `DESIGN.md` **คุมทั้งระบบ รวมหน้าของโครงที่เขาไม่เคยเห็น** — ล็อกอิน แจ้งปัญหา คู่มือ จัดการผู้ใช้

โปรเจคทดสอบเป็นเว็บโชว์ที่ไม่มีฟอร์มสักหน้า ผลคือ

| token | ได้มา | อาการ |
|---|---|---|
| `layout.formWidth` · `fieldMinWidth` | `"0px"` พร้อมคอมเมนต์ *"เว็บนี้ไม่มีฟอร์ม"* | ฟอร์มล็อกอินและฟอร์มแจ้งปัญหาของโครงยุบเหลือศูนย์ |
| **`color.border.strong`** | `#C3BCB0` / `#3F4A47` | ‼️ **ตกเกณฑ์ 3:1 ทั้ง 6 คู่** |

`border.strong` เจ็บที่สุดเพราะเหตุผลของเขา**ถูกสำหรับหน้าที่เขาเห็น** — เขาเขียนไว้ชัดว่าเส้นขอบเป็นของตกแต่ง ขอบเขตถูกบอกซ้ำด้วยพื้นและระยะอยู่แล้ว ซึ่งจริงสำหรับการ์ดสินค้า

**แต่ในโครง `border.strong` คือเส้นขอบของ control ที่ WCAG 1.4.11 บังคับ 3:1**

> `check-contrast.php` จับได้ตอนนำเข้า ซึ่งคือเหตุผลที่ B6 ต้องรันทุกครั้ง ไม่ใช่รันเฉพาะตอนสงสัย

เพิ่มหัวข้อ **"token ที่โครงใช้ แม้หน้าในสโคปจะไม่ใช้"** ใน `flow.md` B3 — ต้องเขียนกำกับในแบบฟอร์มว่า **ห้ามตอบ `0` ห้ามเว้นว่าง ห้ามตอบว่าไม่เกี่ยว**

### ‼️ 2. `:root` ที่ได้กลับมาใช้ชื่อของผู้ออกแบบเอง

ขอไปว่า *"ขอ `:root` ที่เติมค่าครบทุก token"* ได้กลับมาเป็น `--fs-base` แทน `--text-base` · `--sp-4` แทน `--space-4` · `--table-row-h` แทน `--table-row-height`

**รอบนี้รอดเพราะเขาแนบบล็อก YAML ตามแบบฟอร์มมาให้ด้วยโดยไม่ได้ขอ** — ซึ่งเป็นความบังเอิญ ไม่ใช่กฎ

ต่อไปนี้ต้อง**ขอสองอย่างคู่กัน** — `:root` เอาไว้ดูของจริงในเบราว์เซอร์ · **บล็อก YAML เป็นข้อความ** เอาไว้คัดลอกเข้า `DESIGN.md`

### ‼️ 3. ไฟล์ที่ได้กลับมาอ่านด้วย `grep` ไม่ได้

ไฟล์จาก Claude Design เป็น **bundle ที่แตกตัวเองด้วย JavaScript**

`grep '<section id'` ได้ **0 บรรทัด ทั้งที่มีจริงครบ 8 หน้า** — และนั่นคือกับดัก เพราะมันดูเหมือนผู้ออกแบบไม่ได้ทำตามสเปค

**ทุกการตรวจในขั้นนำเข้าต้องทำผ่านเบราว์เซอร์** และเพิ่มกฎย่อยว่า **ต้องเก็บ snapshot ของค่าก่อนสลับโหมด** เพราะ `getComputedStyle()` คืน object ที่มีชีวิต — อ่านซ้ำด้วยตัวแปรเดิมจะได้ค่าเท่ากันเสมอ แล้วสรุปผิดว่าโหมดมืดไม่ทำงาน

### เพิ่มในตารางการแปลงตอนนำเข้า

ระยะห่าง มุม ไอคอน มักได้มาเป็นตัวเลขเปล่า `16` ต้องใส่ `px` · ระยะเวลา `160` ต้องใส่ `ms` · และ**ค่าที่อ้างถึง token อื่น** (`"surface.raised"` · `"1px solid border.normal"`) ต้องแปลงเป็น `var()` **ไม่ใช่ค่าสีตายตัว** ไม่งั้นมันจะไม่เปลี่ยนตามโหมด

wireframe ไม่เคยทำหน้าที่ "ออกแบบ" มันทำหน้าที่ตัดสินว่า **มีหน้าอะไร และแต่ละหน้ามีอะไรอยู่บ้าง** ซึ่งเป็นการตัดสินใจเรื่อง**ขอบเขตงาน** ไม่ใช่เรื่องหน้าตา

ยกให้ Claude Design โดยไม่มีอะไรมาแทน = **เขาจะเป็นคนตัดสินว่าเว็บมีกี่หน้า** ทั้งที่เขาไม่เคยเห็น `SCOPE.md`

> ‼️ **"หน้าที่จงใจไม่มี พร้อมเหตุผล"**
> ไม่เขียนไว้ เขาจะใส่หน้าติดต่อ หน้าราคา หน้าสมัครสมาชิกมาให้ **เพราะเว็บแบบนั้นทุกเว็บมี**
> โปรเจคทดลอง SALA ตัดหน้าติดต่อออกโดยตั้งใจ ซึ่งไม่มีทางที่ใครจะเดาถูก

### เพิ่ม `partials/table.php` — ตารางหน้ารายงานของกลาง

`components.md` เรียกมันว่า *"component ที่ซับซ้อนที่สุดและใช้บ่อยที่สุด"* แต่โครงมีแค่ชิ้นส่วน (`.table` · `th-sort` · `pagination` · `empty-state`) ไม่มีตัวประกอบ — แต่ละหน้าจึงต่อเองคนละแบบ


### ดึงเปลือกของ `<dialog>` ออกมาเป็น `partials/dialog.php`

ทดสอบด้วยการวางกล่องที่สองในหน้าเดียวกันจริง — เปิด ปิด และ `id` แยกกันถูกต้อง โดยไม่ต้องเขียน JS ใหม่

### ⚠️ `structure/partial-input-contract` จับ include ได้ไม่ครบ

การตรวจที่เพิ่งเพิ่มใน 3.2.3 จับเฉพาะรูปที่มี `partials/` นำหน้า จึงมองไม่เห็นรูปที่ partial เรียกกันเอง

> เป็นบทเรียนเดียวกับ 3.2.3 อีกครั้ง — **การตรวจที่ไม่เคยถูกทดสอบว่าจับของจริงได้ ก็คือการตรวจที่ยังไม่รู้ว่าทำงานหรือเปล่า**

- ตรวจ plugin กลุ่มบังคับจาก `~/.claude/settings.json`

ท้ายผลลัพธ์บอกเสมอว่าเหลืออะไรที่คนต้องทำเอง — เหลือแค่ **2 อย่าง** คือติดตั้ง plugin (ต้องเปิด session ใหม่) และรหัส MySQL ที่ไม่ใช่ค่าตั้งต้น

### `SessionStart` hook ตรวจความพร้อมให้ตั้งแต่วินาทีแรก

`scripts/hooks/session-start.php` เรียก `setup.php --check` ทุกครั้งที่เปิด session ถ้ายังไม่ครบจะสั่งให้ AI รัน setup เองก่อนทำอย่างอื่น

ทำได้เพราะ `.claude/` ติดมากับการ clone (ต่างจาก `.git/hooks/` ที่ไม่ติด) — จึงเป็นจุดเดียวที่รู้ได้ก่อนที่ผู้ใช้จะพิมพ์อะไร

### ⚠️ แก้บั๊กที่ทำให้ clone สดๆ บน Windows ใช้งานไม่ได้เลย

**clone มาแล้วรัน `check.php` ทันที จะ fail 20 ข้อ ทั้งที่ยังไม่ได้แตะโค้ดสักบรรทัด** — แล้ว pre-commit hook จะบล็อกทุก commit ตั้งแต่วันแรก

สาเหตุ: Git for Windows แปลง LF เป็น CRLF ตอน checkout ทำให้เนื้อไฟล์ต่างจากตอนที่คำนวณลายเซ็นไว้

- `docs/standard-untouched` เทียบ sha256 ไม่ตรงทั้ง 19 ไฟล์ → รายงานว่ามีคนแก้มาตรฐาน
- `design/css-in-sync` เทียบ `app.css` กับที่ generate จาก `DESIGN.md` ไม่ตรง

แก้ 2 ชั้น

1. เพิ่ม **`.gitattributes`** บังคับ `* text=auto eol=lf` — กันที่ต้นทางทุกเครื่อง
2. **hash และเทียบไฟล์โดยไม่สนใจ LF/CRLF** — เผื่อ config ของเครื่องใครไป override

> เครื่องที่ clone ไว้ก่อนเวอร์ชันนี้ ให้รัน `git add --renormalize .` หนึ่งครั้ง

### เพิ่ม `scripts/lib/Manifest.php` — ลายเซ็นมาตรฐานมีที่คำนวณเดียว

โค้ดคำนวณลายเซ็นเคยมี **สองชุด** ที่ `standard-update.php` (ตอนเขียน) กับ `checks/docs.php` (ตอนตรวจ)

พอแก้วิธี hash ที่ชุดเดียวเพื่อกัน CRLF อีกชุดคิดคนละแบบทันที แล้วรายงานว่ามาตรฐานถูกแก้ทั้งชุดทั้งที่ไม่มีใครแตะ — ตรงกับกฎ **"ทุกอย่างเป็นของกลาง แก้ที่เดียวเปลี่ยนทั้งระบบ"** ที่มาตรฐานบังคับไว้เอง แต่ตัวมาตรฐานละเมิดเสียเอง

### ปิดช่องที่ `AGENTS.md` เพี้ยนจาก `CLAUDE.md` แบบเงียบ

`AGENTS.md` คือ `CLAUDE.md` ที่เปลี่ยนชื่อไฟล์ตัวเอง สำหรับ AI ตัวอื่นที่อ่านชื่อนี้ — แต่เดิม**ไม่มีอะไรจับว่าสองไฟล์ต่างกัน** และ `AGENTS.md` ก็ไม่อยู่ในลายเซ็นมาตรฐานด้วย

ผลคือแก้กฎที่ `CLAUDE.md` แล้วลืมอีกไฟล์เมื่อไหร่ AI คนละตัวจะทำงานคนละกฎทั้งที่อยู่โปรเจคเดียวกัน

- เพิ่มการตรวจ **`docs/agents-md-in-sync`**
- `standard-update.php` generate `AGENTS.md` ใหม่ทุกครั้งที่ `CLAUDE.md` เปลี่ยน

### ⚠️ แก้บั๊ก hook ค้าง

`hook_run()` เปิดท่อ stdout กับ stderr แยกกันแล้วอ่าน stdout จนจบก่อน — ถ้าคำสั่งเขียน stderr มากพอจนท่อเต็ม ทั้งสองฝั่งจะรอกันไปมาไม่มีใครขยับ **hook ค้างเท่ากับ Claude Code ค้างตามไปจนหมด timeout**

เจอตอนทดสอบ `setup.php` เพราะ `composer` เขียน output ทั้งหมดลง stderr — แต่บั๊กนี้มีอยู่ใน `guard-commit` มาตั้งแต่ 3.0 แล้ว จะโผล่เมื่อ `check.php` รายงาน error จำนวนมาก

แก้โดยรวม stderr เข้า stdout ด้วย `2>&1` แล้วใช้ท่อเดียว (`stream_select` ใช้กับ pipe ของ `proc_open` บน Windows ไม่ได้)

### กฎใหม่ที่มาจากสิ่งที่ AI มักลืม

| กฎ | ผลถ้าไม่มี |
|---|---|
| **ทุก resource ต้องครบลูป ดู/เพิ่ม/แก้/ลบ** | หน้าที่เพิ่มได้แต่แก้ไม่ได้ลบไม่ได้ ใช้งานจริงไม่ได้ |
| ทุก component ต้องมีสถานะ **ว่าง / กำลังโหลด / ผิดพลาด** | ระบบดูค้างและไม่เสร็จ |
| **ปุ่ม submit ต้องกันกดซ้ำ** | กดรัวแล้วได้ข้อมูลซ้ำในฐานข้อมูล |
| **ฟอร์มคืนค่าที่กรอกไว้เมื่อ validate ไม่ผ่าน** | ฟอร์ม 15 ช่องต้องกรอกใหม่หมดเพราะผิดช่องเดียว |
| **ตัวกรอง หน้า การเรียง อยู่ใน URL ไม่ใช่ session** | แชร์ลิงก์รายงานไม่ได้ · กด back ค่าหาย · เปิด 2 แท็บตีกัน |
| **confirm ก่อนลบต้องบอกว่าลบอะไร** และปุ่มเขียนคำกริยา | คนอ่านปุ่ม ไม่อ่านข้อความ |
| **ตารางบนมือถือยุบเป็นการ์ด** | ตารางกว้างบนจอเล็กใช้ไม่ได้จริง |
| **ปุ่มในตารางเป็นไอคอนเท่านั้น** + `aria-label` | คอลัมน์กว้างเกินจนตารางอ่านยาก |
| **seeder ต้องมี 50-100 แถว** | ไม่เห็นว่า pagination พังหรือ query ช้าจนขึ้นใช้จริง |
| **เงินเก็บเป็นจำนวนเต็มหรือ `DECIMAL`** ห้าม `FLOAT` | ปัดเศษเพี้ยนแล้วยอดไม่ตรง |

### ความปลอดภัยที่เพิ่ม

- **CSV injection** — ค่าที่ขึ้นต้นด้วย `=` `+` `-` `@` ถูก Excel ตีความเป็นสูตร ต้องเติม `'` นำหน้า (ช่องโหว่ที่เกิดจากการบังคับให้ทุกหน้ารายงานมีปุ่มส่งออก)
- **route `/_migrate`** — ปลายทางที่แก้โครงสร้างฐานข้อมูลได้เปิดอยู่บนอินเทอร์เน็ต ต้อง `hash_equals()` · ตอบ 404 เมื่อ token ผิด · rate limit เข้ม · log ทุกครั้ง
- **security headers** ตั้งที่ `core/Security.php` จุดเดียว — CSP ตั้งเข้มได้เพราะไม่โหลดอะไรจาก CDN อยู่แล้ว
- **ชื่อไฟล์อัปโหลดภาษาไทย** ต้อง sanitize ตอนเก็บ แต่เก็บชื่อเดิมไว้แสดง
