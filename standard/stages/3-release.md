# ส่งขึ้น server ทดสอบ และส่งมอบ

> **ทำครั้งเดียว หลังผ่านประตู D** · ภาพรวมอยู่ที่ [`../flow.md`](../flow.md)
> **การขึ้น production ผู้ใช้ทำเอง ไม่อยู่ในขอบเขตของ workflow นี้** — ไฟล์นี้จบที่ server ทดสอบและการส่งมอบข้อมูลให้ผู้ใช้

---

## 1. ทำความสะอาดก่อน push

- [ ] ลบโค้ดทดสอบ · `var_dump` · `print_r` · `console.log` · route ทดสอบ · ไฟล์ที่ไม่ใช้ ออกให้หมด
- [ ] ไม่มี `TODO` หรือ `FIXME` ค้างที่ยังไม่ได้ตัดสินใจ — ถ้ายังไม่ทำ ต้องอยู่ใน `SCOPE.md` หัวข้อ "ไม่อยู่ในขอบเขต" หรือใน `QUESTIONS.md`
- [ ] `project/SCOPE.md` ติ๊กครบและตรงกับของที่ทำจริง · `project/PLAN.md` สถานะตรงความจริง · `project/STATE.md` อัปเดตแล้ว
- [ ] เรียก `/code-review` กับงานทั้งหมด
- [ ] `php scripts/check.php` **ตรวจเต็ม** ผ่าน — ระหว่างทางอาจใช้ `--changed` มาตลอด ขั้นนี้ต้องเต็ม
- [ ] **ไม่มี phase ค้าง 🔨 ใน `PLAN.md`** — โหมดเร็วต้องตรวจย้อนหลังครบในช่วง D แล้ว และ `QA-REPORT.md` มีหัวข้อของทุก phase นั้น (`docs/fast-mode-debt`)

## 2. ความพร้อมของการติดตั้ง

- [ ] **`.env.example` มีตัวแปรครบตรงกับที่ระบบใช้จริง และไม่มีค่าจริงติดไป**
- [ ] **migration ทั้งหมดรันเรียงลำดับจบในครั้งเดียวบนฐานข้อมูลเปล่าได้จริง — ทดสอบจริงแล้ว** ไม่ใช่เชื่อว่าน่าจะได้
- [ ] ‼️ **หลังรัน seeder ต้องอ่านข้อมูลกลับมาเทียบว่าภาษาไทยไม่เพี้ยน — เทียบผ่านโค้ด (PDO) ไม่ใช่ดูจาก console**
  > console บน Windows แสดงภาษาไทยไม่ได้อยู่แล้ว ทำให้แยกไม่ออกว่าข้อมูลเสียจริงหรือแค่แสดงผลเพี้ยน
- [ ] **seeder แยกชัดว่าอันไหนเป็นข้อมูลตั้งต้นที่ต้องรันจริง อันไหนเป็นข้อมูลตัวอย่างที่ห้ามรันบน production**
- [ ] README ครบทุกหัวข้อ — **ให้คนที่ไม่เคยเห็นระบบทำตามแล้วรันขึ้นได้จริง**
- [ ] **มีแผนสำรองข้อมูล** — ใครสำรอง ทุกกี่วัน เก็บที่ไหน กู้คืนอย่างไร · cron ของ `scripts/backup.php` ตั้งแล้ว
  > ระบบธุรกิจที่ไม่มี backup คือระบบที่รอเวลาพัง
- [ ] **มีนโยบายขนาดตาราง `audit_logs`** ว่าจะเก็บย้อนหลังกี่เดือนแล้วย้ายไป archive

## 3. Git

**Commit message** — `type: คำอธิบาย` เช่น `feat: เพิ่มระบบตะกร้าสินค้า` · `fix: แก้บั๊กคำนวณราคาผิด`

- [ ] `git status` สะอาด ไม่มีไฟล์ที่ไม่ควร commit ค้างอยู่
- [ ] **ยืนยันว่า `.env` ไม่ได้ถูก commit ขึ้นไป**
- [ ] `fetch` / `pull` เช็คว่า `main` มีการเปลี่ยนแปลงจากคนอื่นระหว่างที่ทำงานอยู่หรือไม่
- [ ] **ถ้าพบความเสี่ยง conflict → แจ้งรายละเอียดให้ผู้ใช้ก่อน ห้าม merge หรือ push ทับเอง**
- [ ] push branch แล้วเปิด PR

> **การ merge เข้า `main` ผู้ใช้ทำเอง** — AI เปิด PR และรายงานเท่านั้น
> **ห้ามทำโดยไม่ขออนุญาต:** `force push` · `reset` ประวัติ · ลบ branch ของคนอื่น

### เมื่อผู้ใช้สั่งให้แตะ `main` เองจริงๆ

กฎเหล็กมีข้อยกเว้นอยู่แล้วว่า "ยกเว้น commit แรกตอนตั้งโปรเจค หรือผู้ใช้สั่งเอง"
แต่ hook มองไม่เห็นเจตนาของผู้ใช้ จึงต้องให้**ผู้ใช้เขียนคำอนุญาตลงในคำสั่งตรงๆ**

```bash
WF_ALLOW_MAIN=1 git push origin main
```

| ทำไมออกแบบแบบนี้ | |
|---|---|
| ต้องพิมพ์เพิ่มเอง | ทำโดยบังเอิญไม่ได้ |
| เห็นอยู่ในคำสั่ง | ตรวจย้อนหลังได้ว่าใครอนุญาตเมื่อไหร่ |
| ครอบเฉพาะเรื่อง `main` | **`force push` ยังถูกบล็อกอยู่แม้จะใส่คำอนุญาตนี้** เพราะเป็นคนละเรื่องกัน |

> ‼️ **AI ห้ามเติมคำอนุญาตนี้เองถ้าผู้ใช้ไม่ได้สั่งในรอบนั้น** — ใส่เองเมื่อไหร่เท่ากับข้ามกฎ
> ไม่ใช่ช่องทางลัดสำหรับความสะดวก แต่เป็นวิธีเดียวที่ทำให้ hook แสดงข้อยกเว้นที่กฎมีอยู่แล้วได้

## 4. CI ทำอะไรให้

`.github/workflows/deploy.yml` ทำงานเมื่อ `main` เปลี่ยน

```
php scripts/check.php  →  ไม่ผ่าน = หยุด ไม่อัปไฟล์
    ↓ ผ่าน
เปิด maintenance mode  →  อัปไฟล์ผ่าน FTP  →  ยิง /_migrate  →  ปิด maintenance mode
```

**ถ้า `check.php` ไม่ผ่าน ไฟล์จะไม่ถูกอัปเลย** — นี่คือกำแพงสุดท้ายที่ไม่ขึ้นกับว่าใครจำได้ไหม

## 5. ตรวจหลัง deploy — บน server จริงเท่านั้น

**ห้ามถือว่าเสร็จเพราะทดสอบผ่านบนเครื่อง local แล้ว** — ปัญหาที่เจอบ่อยตอนขึ้นจริงคือ path, สิทธิ์ไฟล์, timezone และเวอร์ชัน PHP ที่ต่างกัน

- [ ] เปิดหน้าแรกและ login ได้จริง
- [ ] ‼️ **เปิด `https://โดเมน/.env` ในเบราว์เซอร์แล้วเข้าไม่ได้** · ลองเปิด path ของ `app/` `storage/` `standard/` ตรงๆ แล้วเข้าไม่ได้
- [ ] `APP_ENV` เป็น `production` และ `display_errors` ปิดแล้ว
- [ ] HTTPS ทำงานและ redirect จาก http
- [ ] `storage/logs/` และโฟลเดอร์อัปโหลดเขียนได้
- [ ] ทำ 1 flow หลักให้ครบตั้งแต่ต้นจนจบด้วยข้อมูลจริง
- [ ] **audit log บันทึกบนเครื่องจริงได้ และเวลาที่บันทึกเป็นเวลาไทยถูกต้อง**
- [ ] ทำให้เกิด error จริง 1 ครั้ง → ผู้ใช้เห็นแค่ข้อความทั่วไปพร้อมรหัสอ้างอิง **ไม่เห็น stack trace** และ log เขียนลงไฟล์ได้จริง
- [ ] ปุ่มแจ้งปัญหาส่งเรื่องเข้ามาได้ และหน้าแอดมินเปิดดูได้
- [ ] ภาษาไทย จีน และ emoji ไม่เพี้ยนบนเครื่องจริง
- [ ] **สลับภาษาได้ทุกภาษาที่เปิดใช้** และวันที่แสดงถูกต้องตามภาษา
- [ ] **สลับโหมดสว่าง/มืดได้ ไม่มี flash**
- [ ] เปิดหน้า `/manual` ได้ และ**รูปประกอบคู่มือโหลดขึ้นครบ** ← path ของรูปเป็นจุดที่พังบ่อยที่สุดตอนขึ้นเครื่องจริง
- [ ] **เปิดด้วยมือถือจริง 1 เครื่อง** ไม่ใช่แค่ย่อหน้าต่างเบราว์เซอร์

## 6. ส่งมอบข้อมูลให้ผู้ใช้

รายงานให้ผู้ใช้ทราบก่อนที่เขาจะเอาขึ้น production เอง

- [ ] **URL ระบบบน server ทดสอบ · บัญชีแอดมินตั้งต้น (ให้เปลี่ยนรหัสผ่านทันที) · วิธีดู audit log · วิธีดูเรื่องที่แจ้งเข้ามา · URL หน้าคู่มือ**
- [ ] อธิบายวิธีอ่านรหัสอ้างอิง error เวลาผู้ใช้แจ้งปัญหามา
- [ ] **สิ่งที่ต้องตั้งบน production เอง** — `.env` ใหม่ · `MIGRATE_TOKEN` ใหม่ · document root ที่ `public/` · HTTPS · cron backup · seeder ตัวไหนห้ามรัน
- [ ] บอกคนที่ดูแลต่อว่า**คู่มืออยู่ที่ไฟล์ไหนและต้องแก้พร้อมโค้ด**
- [ ] บอกวิธีเพิ่มภาษาใหม่ภายหลัง
- [ ] ‼️ **แจ้งรายการที่รู้ว่ายังไม่สมบูรณ์หรือยังไม่ได้ทำ** พร้อมระบุว่าอยู่ในหัวข้อ "ไม่อยู่ในขอบเขต" ของ `SCOPE.md` หรือเป็นของที่ค้างจริง
  > ไม่ใช่ปล่อยให้ไปเจอเองบนเครื่องจริง

## 7. ‼️ ปิดวงจร — ส่ง `FEEDBACK.md` กลับไปที่ repo มาตรฐาน

**ขั้นนี้คือขั้นเดียวที่ทำให้มาตรฐานดีขึ้นได้จริง** ข้ามแล้วโปรเจคหน้าจะเจอปัญหาชุดเดิมทั้งหมด

- [ ] เปิด `project/FEEDBACK.md` อ่านทุกข้อที่ยังเป็น `[ ]`
- [ ] **สรุปให้ผู้ใช้เป็นรายการสั้นๆ** ว่ารอบนี้มาตรฐานพลาดตรงไหนบ้าง และข้อไหนตรวจด้วยเครื่องได้
- [ ] บอกให้เขาเอาไปเปิด issue หรือ PR ที่ repo มาตรฐานกลาง ([`../README.md`](../README.md) หัวข้อ "อยากเสนอแก้มาตรฐาน")
- [ ] ‼️ **ห้ามติ๊ก `[x]` ตรงนี้** — ติ๊กได้ต่อเมื่อกฎกลางถูกแก้จริงแล้ว พร้อมเขียนกำกับว่าเข้าเวอร์ชันไหน

> ‼️ **ไฟล์นี้ว่างเปล่าตอนจบโปรเจค เป็นสัญญาณที่ไม่ดี ไม่ใช่สัญญาณที่ดี**
> ไม่มีโปรเจคไหนเดินครบ A-E แล้วไม่เจออะไรเลยสักข้อ · ว่างเปล่าแปลว่า**ไม่ได้บันทึกตอนที่มันเกิด** ไม่ใช่ว่ามาตรฐานสมบูรณ์แล้ว
>
> ดูประวัติของชุดนี้เป็นหลักฐาน — ทุกเวอร์ชันตั้งแต่ 3.6.2 ถึง 3.12.0 เกิดจากของที่เจอตอนใช้จริงทั้งหมด **ไม่มีเวอร์ชันไหนเกิดจากการนั่งคิดในห้อง**
