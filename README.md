# โครงมาตรฐานของทีม

มาตรฐานกลางสำหรับสร้างเว็บ/ระบบด้วย PHP + MySQL โดยสั่งงาน AI แทนการเขียนเอง
clone แล้วพิมพ์ `/wf` ครั้งเดียว จากนั้นตอบเป็นภาษาคนธรรมดา

เวอร์ชันมาตรฐานอยู่ที่ [`standard/VERSION`](standard/VERSION) — ดูสิ่งที่เปลี่ยนที่ [`standard/CHANGELOG.md`](standard/CHANGELOG.md)

---

## เริ่มยังไง — 2 ขั้น

### 1. clone แล้วตั้งชื่อโปรเจค

```bash
git clone <url ของ repo มาตรฐาน> ชื่อโปรเจคใหม่
```

### 2. เปิด Claude Code ในโฟลเดอร์นั้น แล้วพิมพ์

```
/wf
```

**จบแค่นั้น** — ไม่ต้องพิมพ์คำสั่งตั้งค่าอะไรทั้งสิ้น

> ‼️ **รวมถึงการตัด repo มาตรฐานออกด้วย** — `git clone` พา `.git` มาทั้งก้อน `origin` จึงยังชี้ไป repo มาตรฐาน และประวัติของมาตรฐานหลายสิบ commit ปนอยู่ในโปรเจคของคุณ
>
> `setup.php` ตรวจเจอเองตั้งแต่ขั้น A0 แล้วบอก AI ให้จัดการ · **คุณแค่ตอบว่าใช่ นี่คือโปรเจคใหม่**
> จากนั้นมันจะเก็บ url ของ repo มาตรฐานลง `.standard-source` (ไว้ให้ `standard-update.php` ใช้) → เริ่ม git ใหม่ → commit แรก → เปิด pre-commit hook ให้ครบในคำสั่งเดียว
>
> **ทำไมไม่ตัดให้เองเงียบๆ** — repo มาตรฐานกลางกับ clone สดๆ หน้าตาเหมือนกันทุกอย่าง ต่างกันแค่เจตนา ซึ่งเครื่องดูไม่ออก · เดาผิดคือทำลายประวัติของ repo กลางเอง

พอเปิด session ระบบจะรู้เองว่าเครื่องนี้ยังตั้งค่าไม่ครบ แล้วรัน `scripts/setup.php` ให้ ซึ่งจัดการทุกอย่างที่ทำแทนได้

| ทำให้อัตโนมัติ | |
|---|---|
| — | **ไม่มีขั้นติดตั้ง dependency** — clone แล้วเปิดหน้าเว็บได้ทันที |
| สร้าง `.env` จาก `.env.example` | เติมเฉพาะช่องที่ว่าง **ไม่ทับค่าที่กรอกไว้แล้ว** |
| สุ่ม `MIGRATE_TOKEN` | 64 ตัวอักษร ใหม่ทุกโปรเจค |
| ตั้ง `APP_ENV=development` | เห็น error จริงบนเครื่องตัวเอง · `.env` ไม่ขึ้น git จึงไม่ติดไปถึง server |
| เปิด pre-commit hook | **แล้วทดสอบด้วยไฟล์ที่ผิดกฎจริง** ว่าบล็อกได้ ไม่ใช่แค่ตั้งค่าแล้วเชื่อว่าทำงาน |
| สร้างฐานข้อมูล | charset `utf8mb4_unicode_ci` · ถ้ามีอยู่แล้วแต่ charset ผิดจะเตือน |
| รัน migration | |
| ตรวจ plugin ที่บังคับ | |

รันซ้ำเมื่อไหร่ก็ได้ ไม่พัง — หรือสั่งเองก็ได้

```bash
php scripts/setup.php
```

### สิ่งที่ยังต้องทำเอง

มีอยู่ **2 อย่าง** และสคริปต์จะบอกท้ายผลลัพธ์ว่าติดข้อไหน

| | ทำไมทำแทนไม่ได้ |
|---|---|
| **ติดตั้ง plugin ที่บังคับ** | `/plugin install` เปิดหน้าต่างเลือกแบบโต้ตอบ และหลังติดตั้งต้อง**เปิด session ใหม่** จึงต้องทำก่อนคุยเรื่องงาน ไม่งั้นบทสนทนาที่เก็บความต้องการไว้หายหมด |
| **รหัสผ่าน MySQL** ถ้าไม่ใช่ค่าตั้งต้น | สคริปต์ลองเฉพาะ `root` แบบไม่มีรหัสและ `root/root` บนเครื่องตัวเองเท่านั้น — เดารหัสจริงให้ไม่ได้และไม่ควรเดา · บอกมาแล้วให้ AI เติมให้ |

รายการ plugin อยู่ที่ [`standard/skills.md`](standard/skills.md)

## รันบนเครื่องตัวเอง

```bash
php server.php
```

เปิดที่ `http://localhost:8000` — ใช้บนเครื่องตัวเองเท่านั้น **ห้ามอัปขึ้น server จริง**

---

## ‼️ ตั้ง document root ที่ `public/` เท่านั้น

ข้อนี้สำคัญที่สุดต่อความปลอดภัย ชี้ผิดแล้ว `.env`, `storage/` และซอร์สโค้ดทั้งหมดจะโหลดได้จากเบราว์เซอร์ทันที

**ตรวจด้วยการเปิด `https://โดเมน/.env` ในเบราว์เซอร์ — ต้องเข้าไม่ได้**

## คำสั่งที่ใช้บ่อย

| คำสั่ง | ทำอะไร |
|---|---|
| `php scripts/setup.php` | ตั้งค่าเครื่องนี้ให้พร้อมทำงาน (รันซ้ำได้) |
| `php scripts/check.php` | ชุดตรวจมาตรฐานทั้งหมด |
| `php scripts/check.php --list` | ดูรายการตรวจทั้งหมด |
| `php scripts/check-contrast.php` | ตรวจ contrast ของ token ทุกคู่ ทั้งสองโหมด |
| `php scripts/check.php lang` | ตรวจเฉพาะกลุ่ม |
| `php scripts/design-sync.php` | `project/DESIGN.md` → `public/assets/css/app.css` |
| `php scripts/migrate.php --status` | ดูว่ารัน migration อะไรไปแล้ว |
| `php scripts/migrate.php --export` | รวม migration ที่ค้างเป็นไฟล์เดียวไว้ import ผ่าน phpMyAdmin |
| `php scripts/backup.php` | สำรอง DB + ตัด log + ย้าย audit เก่าเข้าคลัง (ตั้ง cron) |
| `php scripts/check.php --changed` | ตรวจไฟล์ที่เปลี่ยน + การตรวจทั้งโปรเจค — ใช้ระหว่างทำ |
| `php scripts/design-refs.php --import <โฟลเดอร์>` | นำเข้าภาพแบบที่ออกแบบเอง · `--palette` `--pick` วัดสีจากภาพ · `--status` หน้าไหนเทียบกับแบบแล้ว |
| `php scripts/standard-update.php` | ดูว่าอัปเดตมาตรฐานแล้วจะเปลี่ยนอะไร (ไม่เขียนอะไร) · เติม `--yes` เพื่อลงมือ |

## โครงสร้างโดยย่อ

```
standard/   มาตรฐานกลาง — อ่านอย่างเดียว ‼️ ห้ามแก้ในโปรเจค
project/    เอกสารของโปรเจคนี้ — /wf เขียนที่นี่
core/       Router · Path · Database · Model(+audit log) · Auth · Security · …
app/        Controllers · Services · Models · Middlewares · Views
config/     config.php (ที่เดียวที่อ่าน .env) · routes.php · manuals.php
lang/       th.php · en.php — ‼️ บังคับอย่างน้อย 2 ภาษาทุกโปรเจค
database/   migrations/ · seeders/
public/     ‼️ document root ต้องชี้มาที่นี่
scripts/    ‼️ ของมาตรฐาน ห้ามแก้ในโปรเจค — setup · ชุดตรวจ · design-sync · migrate · backup · hooks
storage/    logs · uploads (นอก public/) · backups
```

## กฎที่ต้องรู้ก่อนแตะโค้ด

กฎเต็มอยู่ที่ [`CLAUDE.md`](CLAUDE.md) — ต่อไปนี้คือข้อที่พลาดแล้วเจ็บที่สุด

| กฎ | ทำไม |
|---|---|
| **`standard/` · `scripts/` ห้ามแก้ในโปรเจค** | แก้แล้วผ่านไป 3 เดือน แต่ละโปรเจคจะมีมาตรฐานคนละตัว · ต้องเบี่ยงเบนให้บันทึกที่ `project/NOTES.md` |
| **ทุก query ใช้ prepared statement 100%** | ห้ามต่อ string เข้า SQL ไม่ว่ากรณีใด |
| **ทุกลิงก์ผ่าน `url()`** | ระบบต้องเปิดได้ทั้งที่ root และใต้ subdirectory |
| **ทุกข้อความผ่าน `__()`** | เพิ่มภาษาทีหลังจะได้ไม่ต้องไล่แก้ทุกหน้า |
| **ทุกไฟล์ `.sql` ขึ้นต้นด้วย `SET NAMES utf8mb4`** | ไม่มีแล้วภาษาไทยเพี้ยน **โดยไม่มี error แจ้ง** และกู้ไม่ได้ |
| **ค่าธีมอยู่ที่ `project/DESIGN.md` จุดเดียว** | `app.css` generate จากไฟล์นั้น ห้ามแก้ CSS ตรง |
| **audit log มาเองจาก base Model** | เขียนข้อมูลด้วยวิธีที่ไม่ผ่าน Model ต้องบันทึกเองที่จุดนั้น |
| **`check.php` fail ให้แก้ที่โค้ด** | ห้ามแก้ที่สคริปต์ตรวจให้ผ่าน |

## ขึ้น server ทดสอบ

`push` ขึ้น `main` แล้ว GitHub Actions ทำให้อัตโนมัติ

```
ตรวจ check.php → ไม่ผ่าน = หยุด ไม่อัปไฟล์
    ↓ ผ่าน
เปิด maintenance → อัป FTP → ยิง /_migrate → ปิด maintenance → ตรวจว่าเปิดหน้าได้
```

**Secrets ที่ต้องตั้งใน GitHub:** `FTP_HOST` · `FTP_USER` · `FTP_PASS` · `APP_URL` · `MIGRATE_TOKEN`

การขึ้น production ทำเอง ไม่อยู่ในขอบเขตของ workflow นี้

## ตัวแปรใน `.env`

คำอธิบายทุกตัวอยู่ในไฟล์ [`.env.example`](.env.example) แล้ว — ตัวที่ต้องระวังเป็นพิเศษ

| ตัวแปร | ระวังอะไร |
|---|---|
| `APP_ENV` | **default เป็น `production`** ตั้ง `development` เฉพาะบนเครื่องตัวเอง · ลืมเปลี่ยนกลับ = เปิดแสดง error ให้คนนอกเห็น |
| `MIGRATE_TOKEN` | สุ่มใหม่ทุกโปรเจค · เปลี่ยนทันทีถ้าเคยหลุดเข้า log, commit หรือ URL ที่แชร์ |
| `APP_LOCALES` | `th,en` เป็นค่าบังคับขั้นต่ำ |

## ตั้ง cron บนเครื่องจริง

```
0 3 * * * php /path/to/scripts/backup.php
```

สำรองฐานข้อมูล ตัด log ที่โตเกิน และย้าย audit log เก่าเข้าคลัง

> ระบบธุรกิจที่ไม่มี backup คือระบบที่รอเวลาพัง

## อัปเดตมาตรฐานในโปรเจคที่ทำอยู่

**บอก Claude ว่า "อัปเดตมาตรฐาน"** — มันจะให้ดูก่อนว่าจะเปลี่ยนอะไร แล้วลงมือเมื่อคุณอนุญาต บน branch แยก · ขั้นตอนเต็มที่ [`standard/flow.md`](standard/flow.md) ข้อ 14

| ถูกทับ | ไม่แตะ |
|---|---|
| `standard/` · `CLAUDE.md` · `scripts/` · `.claude/commands/` · รวมค่า `.claude/settings.json` | `project/` ทั้งหมด (แผน สถานะ ดีไซน์) · โค้ดของโปรเจค |

> ‼️ **โปรเจคที่ยังไม่มีโฟลเดอร์ `scripts/upgrades/`** — updater ในโปรเจครุ่นนั้นทับได้แค่ `standard/` กับ `CLAUDE.md`
> ครั้งแรกให้ Claude รัน updater จาก repo กลางที่ clone มาใหม่แทน ([`standard/flow.md`](standard/flow.md) ข้อ 14 หัวข้อ "โปรเจคที่ updater ยังเป็นรุ่นเก่า") หลังจากนั้นใช้ปกติ

## อยากเสนอแก้มาตรฐาน

**ห้ามแก้ใน `standard/`** — บันทึกสิ่งที่เจอลง **`project/FEEDBACK.md`** พร้อมตัวอย่างจริงที่ทำให้ติด และ **คำตอบว่าตรวจด้วยเครื่องได้ไหม** แล้วเปิด issue หรือ PR ที่ repo มาตรฐานกลาง

> ‼️ **ไม่ใช่ `QUESTIONS.md`** — ไฟล์นั้นมีวงจรคือ ถาม → ผู้ใช้ตอบ → ติ๊ก `[x]` · ช่องว่างของมาตรฐานที่ถูกติ๊กแปลว่า "จัดการแล้ว" ทั้งที่กฎกลางยังไม่ถูกแก้สักตัว

วิธีเต็มอยู่ที่ [`standard/README.md`](standard/README.md)

> กฎที่ดีที่สุดมาจากความเจ็บจริงในโปรเจค ไม่ได้มาจากการนั่งคิดในห้อง
